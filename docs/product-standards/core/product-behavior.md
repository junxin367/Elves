# Elves 产品行为与交互规范

本文记录已确认的产品行为与交互约定，适用于 Elves Windows 客户端、独立 Harness 工作区及其网页、PWA、Android 远程会话能力。项目不再提供 Codex App 注入。通用设计遵循根目录 [DESIGN.md](../../../DESIGN.md)，本文记录 Elves 的具体约定及明确例外；按主题查阅 [产品规范索引](../README.md)。

新增或调整产品约定时，维护对应章节，并同步核对实现处的需求注释和相关使用说明。

## 项目地址与发布来源

当前 GitHub 仓库为 `https://github.com/junxin367/Elves`。项目主页、问题反馈、仓库元数据及桌面和 Android 应用更新均使用该仓库；Android 发布脚本的固定仓库校验须与客户端更新来源一致。产品名统一为 `Elves`，执行和管理产品独立命名为 `Harness`，远程会话只是其网页及 Android 能力。当前 crate 和产物使用 `elves-*`；旧数据目录、协议字段、Android applicationId 和签名材料按兼容需要保留。

历史发布说明、签名配置回执及验收记录保留当时的仓库归属；迁移代码不表示旧仓库的 Release、Issues 或 Secrets 已迁移。

## 产品 logo 与图标

产品统一使用用户提供的 `03-neon-separated.svg`，仓库唯一源文件为 `assets/harness/icons/elves-logo.svg`。网页、启动页及 README 直接使用 SVG；Windows 应用、托盘和安装程序使用多尺寸 ICO，PWA、Apple touch 及 Android 原生资源使用所需尺寸的 PNG。项目及 Codex、Claude 实例图标保留原值。

资源名称须反映实际用途：`elves-app-icon`、`elves-startup-logo`、`elves-about-logo`、`elves-pwa-192`、`elves-pwa-512`、`elves-apple-touch-icon`，以及 Android 的 `elves_login_logo`、`elves_launcher_foreground`、`elves_launcher_monochrome`。使用 `npm --prefix apps/elves-management run assets:brand` 从唯一 SVG 源重建派生资源，不手工修改各端副本。

Android 前景采用 75% 缩放，使原图约 78% 的图案在 108dp 画布内占约 63dp，保留 66dp 安全区域；背景色保持源 SVG 的 `#F6F4FA`，普通、圆形和单色图标共用这一边界。公开 SVG 与其他网页资源使用同一清单、MIME 和摘要校验。

## 远程项目视图

项目目录合并独立 app-server 的已保存项目与同一 Codex Home 中 Codex App 添加的本地项目。按明确项目 ID、同一 Home 的迁移映射或唯一匹配的完整根目录集合去重；同名、共享部分目录的项目分别保留，不从历史会话工作目录生成项目。

Codex 实例设为显示且命中当前筛选时，全部 Codex 项目均可见，包括空项目、App 新增项目和置顶项目。筛选只限制项目下的会话，不得因缺少匹配会话而隐藏 Codex 项目。只筛选 Claude 时，共享项目按匹配的 Claude 会话显示；隐藏的实例不因项目可见而自动显示。

远程项目继承 Codex App 的项目置顶及置顶区、普通项目区的排列顺序，App 后续修改在侧栏刷新时生效。远程明确置顶或取消置顶仅保存在远程服务中，对操作时的 App 排序记录有效；App 后续改变置顶或顺序后，旧远程覆盖失效。仅存在于原生引擎的项目继续使用远程偏好，并按原生顺序补在对应分组后方。

项目同步只读持久化的项目定义、项目 ID 映射、项目顺序和置顶列表，不读取账号、执行队列、审批或 App 内存状态，不连接或驱动 Codex App，也不修改 App 的状态文件。App 尚未迁入原生引擎的项目可以查看文件和选择新建；只有用户明确发送新会话时，才通过独立 app-server 的幂等项目导入接口登记项目。读取失败保留同一 Home 上次成功的项目记录并显示原因，不影响原生项目列表。

## 交互体验规范

### 统一左侧主导航

PC 上 Elves 与 Harness 工作区左侧导航宽 52px，由 36×36px 图标按钮及左右各 8px 留白组成；按钮圆角 10px，沿用当前客户端侧栏背景、悬停背景和前景色，选中项显示圆角底色。默认只显示图标，悬停显示名称，键盘可聚焦并通过 `aria-current` 标识当前页。项目及 Codex、Claude 实例图标沿用现有资源。

Elves 本机客户端从上到下固定为“会话”“代理设置”“会话管理”“远程会话”。网页、PWA、Android 仅显示“会话”，不开放任何管理页面。会话页保留原会话列表、项目分组和聊天工作区；本机进入其他页面只隐藏它，返回后恢复同一会话、草稿、侧边标签和阅读位置。关联会话及侧边嵌入页继续使用既有精简布局。

“代理设置”合并原供应商配置和本地代理，保留供应商接入、模型、切换、测试、运行状态、日志与请求详情。“会话管理”保留原本地会话浏览、项目/时间筛选、单个及批量删除，移除历史会话修复和上下文压缩配置；删除经过独立服务原有删除事务与安全限制。“远程会话”保留网页服务、公网入口、访问密钥、登录锁定和设备授权。

本地协议代理不提供 GPT 推理续接开关、次数限制、日志筛选或续接前后视图，不按推理 Token 数量自动追加模型请求、思考指令或工具调用。旧配置中的续接字段读取时忽略、保存时清除；正常协议转换、模型繁忙时对原请求的重试及上下文压缩保持各自规则。

这三个管理页面的标题、刷新入口、提示信息和内容卡片共用 1000px 内容宽度，固定在主导航右侧的可用区域内水平居中，不铺满宽屏。窄窗口和手机按可用宽度收缩，并保留现有页面内边距及纵向滚动。

代理设置的供应商编辑、新建及聚合供应商二级页同样使用父级 1000px 内容上限；返回／保存工具栏、表单与配置预览保持同一边界，标题和公共提示继续可见，不使用覆盖整个管理窗口的绝对定位。详情与父页共用内容滚动容器，进入详情时显示顶部，返回时恢复父页阅读位置。详情期间隐藏父页状态、速率和日志等内容并保留其组件状态，不能透出、遮挡详情或接收点击；返回后恢复原筛选。详情与吸顶工具栏使用当前主题的不透明背景，菜单及模态框继续由原有独立弹层提供。宽度不超过 860px 时，表单使用单列并清除原有第 2 列定位，标题与操作区分行，操作按钮按剩余宽度换行。

PC 设置固定在导航底部。Windows 独立客户端点击后直接打开设置，不显示菜单或退出项；PC 网页、PWA 点击后仅显示“设置”和“退出”，退出使用既有撤销设备授权逻辑。

手机网页、PWA 及 Android App 不显示左侧主导航，也不保留其 52px 占位。手机网页按既有 `760px` 断点或无悬停粗指针设备判断；Android 容器始终使用此规则，横屏后也不恢复主导航。Windows 独立客户端不因缩窄窗口启用此手机入口。

手机端恢复旧版会话列表底部两个独立按钮：“设置”位于左侧，直接打开设置；“退出”位于右侧，沿用原有退出确认与撤销当前设备授权流程。底部区域独立于会话列表滚动、保留系统底部安全区；抽屉及遮罩从屏幕左边缘展开。切换宽窄屏时复用同一个设置按钮，保留当前会话、列表阅读位置、草稿及授权状态，不重复绑定退出操作。PC 网页恢复宽屏后仍使用原主导航和设置菜单。

管理页面仅通过本机监听入口的 `/management/` 资源及 `/api/management/{command}` 白名单提供，要求一次性原生证明建立的本机 Cookie，并核对实际监听、回环对端和 Host。网页、PWA、Android 的管理页面及全部管理接口返回 403，包括供应商/API 配置、本地代理、请求日志、批量会话浏览及远程访问配置。远程密码、普通设备授权及伪造的客户端标记均不能取得管理权限；远程资源清单及 Android 内置网页包不包含管理页面，旧缓存也不得恢复这些入口。父页只读取固定同源管理文档并用 `srcdoc` 创建持久页面；消息必须校验来源、当前授权与具体窗口。

配置变更由服务保存并通知其他端；每 15 秒检查版本补齐事件。存在本地编辑时保留草稿并提示刷新合并，旧版本保存返回冲突，禁止静默覆盖。外观仍按当前客户端独立保存，管理页面仅继承该客户端的实际颜色、字体和字号。

### 消息区跳转按钮

消息区底部的圆形跳转按钮外边框统一为 `1.5px`。执行中显示三个动态圆点，其他状态显示跳转箭头；沿用现有按钮直径、主题配色及内容中轴定位。

### 项目选择搜索焦点

PC 点击输入区的“选择项目”后，搜索框自动获得焦点，光标位于当前搜索文字末尾，可直接输入；窄 PC 窗口同样生效。Android 和触屏移动网页保留原有焦点行为，不自动唤起搜索输入。通过方向键、Home、End 打开选择器时继续聚焦选项，其他可搜索 Select 不因本约定改变焦点。

### 公共 Select

工作区设置和新建会话中的 Select 使用同一个主题组件。已选项只在右侧显示 `✓`，不因选中加粗或整行填色；鼠标悬停才整行高亮，键盘焦点保留独立轮廓，触屏不保留悬停色。选中、焦点和禁用状态可同时区分。

方向键和 `Home` / `End` 导航选项，`Enter` 确认，`Esc` 收起并恢复触发器焦点；点击外部或 `Tab` 离开时收起。设置内先关闭下拉再处理页面返回。新建时的项目支持按名称或路径搜索。展开方向与边缘避让见[弹出菜单定位](#弹出菜单的水平展开方向)，组件接口见[公共组件](../frontend/workspace-architecture-and-components.md#通用-ui-组件)。

### Elves 安装、启动与 Harness

安装包只部署一个 `elves.exe` 及卸载程序，桌面、开始菜单和完成页只提供“Elves”。Harness 执行与管理后端通过同一程序的 `--harness-service` 模式运行；共享管理前端不生成独立管理器，删除旧 launcher、任务看板和 Codex App 注入代码。

安装包仅在用户明确要求时构建。普通修改、检查、提交推送或单独编译程序，不自动附带安装包构建。

共享管理前端只提交源码、配置及依赖锁定文件，生成目录 `assets/harness/management/` 整体忽略，已跟踪产物移出 Git。本地文件仍用于预览和内嵌；Windows 与 CI 在 Rust 构建前生成管理页，直接运行 Cargo 时缺少入口或其脚本、样式资源必须明确失败并给出生成指引。工作区手写网页、品牌资源、第三方库和内置插件包继续保留，不按整个 `assets/` 目录忽略。

Elves 启动自动准备本机 Harness 并直接进入工作区，不读取远程地址、不要求访问密钥、不显示连接页，也不自动打开远程会话开关。本机入口默认固定回环端口 `45223`，本地代理默认 `45221`，远程网页默认 `45222`；远程监听不能占用前两者。本机初始化失败只显示实际原因与重试。

本机通过 30 秒有效、仅用一次的证明建立独立 HttpOnly Cookie 授权，不进入远程设备清单。远程关闭、只读、换密钥、登录锁定、设备撤销和公网变化都不能影响 Elves 的本机授权、执行或代理。网页、PWA、Android 继续使用远程密钥及设备策略。

独立客户端忽略并移除旧的远程登录标记。本机 Cookie 失效或缺失时，通过仅限原生绑定的本机会话页调用的命令恢复；并发恢复串行执行，仍有效的令牌可复用。恢复保留草稿及待确认回执，不自动重发写操作。失败只展示真实原因及“重试本机连接”，不显示访问密钥输入或远程退出流程。

当前已启用供应商打开“启用本地代理”后，代理随 Elves / Harness 自动启动，运行中开关变化也会生效，不依赖远程网页开关。外观仍按客户端独立保存，其他设置由同一 Harness 的各端共用。

主窗口关闭收进托盘，托盘退出安全回收本客户端拥有的后台。升级请求安全退出并清理旧程序和快捷方式；卸载保留设置、历史、密钥、授权及 WebView 数据。架构细节见 [Elves 与 Harness 架构](../../harness-architecture.md)。

### Elves 原生文件与帮助菜单

Elves 的“文件”“帮助”位于现有 36px 原生顶栏内，不增加第二条菜单栏。菜单按钮点击及聚焦后不绘制边框，悬停、按下和键盘焦点使用背景色提示，保留原生焦点及键盘操作。窗口控制、DPI 缩放、拖动和网页配色同步保持原有约定。网页、PWA 与 Android 不提供宿主机菜单。

“文件 → 添加文件夹”打开原生单目录选择器。确认后，Harness 保存所选目录的项目定义并通知各客户端刷新；重复选择同一实际目录复用项目，取消不改写项目。主窗口返回会话页并选择该项目的新会话输入区，保留此前会话草稿，不自动发送消息、启动模型任务或写入 Codex App 状态。只使用 Claude 或未启用实例时也可以登记项目；用户发送 Codex 会话时才核对并登记对应原生项目。

项目跳转由原生保存请求 ID，主工作区完成显示后确认；页面尚未加载或读取失败时保留请求。用户后来主动切换会话时取消旧跳转，更换授权后旧异步结果不更新界面。网页命令只能读取和确认已登记的项目 ID，不能传入文件系统路径或打开系统选择器。

“帮助”依次为“打开项目地址”“更新”“关于 Elves”。项目地址在默认浏览器打开当前 Elves 仓库。更新只查询公开正式发行版，分别显示当前与公开版本；发现新版本后先确认下载，校验仓库、文件大小及 SHA-256，再确认退出并启动安装。发行版缺少可校验的 Windows 安装包时，明确提示并允许打开项目发布页。失败显示实际原因并允许重试，不在启动时自动更新。“关于 Elves”使用独立小窗口展示 SVG logo、实际程序版本、项目主页和 MIT 协议。

“关于 Elves”每次打开都相对当前主窗口的完整外框居中，按实际显示器 DPI 定位；主窗口部分移出屏幕时，仅平移到同屏工作区内以保持可操作。标题栏只保留关闭按钮，禁止最小化、最大化及拖边缩放。内容区右下角提供“确认”，与标题栏关闭均只销毁关于窗口，不隐藏或退出主窗口、不停止 Harness；确认权限仅授予内置关于页，不能指定其他窗口。

### 远程设置分类与实例配置

设置保持单层导航、分组卡片及统一关闭入口。PC 导航仍为 222px，内容上限仍为 1000px；手机沿用既有独立滚动和 760px 断点，实例说明按剩余宽度换行，开关和选择器保持在对应行内，不产生横向溢出。导航及实例设置页使用集中登记的定义，新增分类须同时登记名称、图标、页面和实际读取接口。

设置弹窗从实际可见的主导航右边开始，保留主导航的视觉位置；没有主导航时仍用全宽。主导航和会话在弹窗打开时不可操作，点击露出的主导航不关闭设置。标题“设置”与关闭按钮固定在设置子导航顶部，仅子导航的分类列表滚动；右侧页面从区域顶部开始独立滚动，原有完成、保存等操作固定在右侧底部。

设置子导航参考 Codex 的文字层级：普通可点击项及图标使用当前主题完整前景色，分组标题使用辅助文字色；悬停、键盘聚焦及选中时保持文字颜色，通过原有背景和焦点轮廓区分状态。该规则适用于 PC、手机及所有明暗、自定义配色，不调整其他区域的全局辅助文字色。

| 分组 | 页面 |
| --- | --- |
| 个人 | 常规、外观、快捷键 |
| 智能体 | 会话实例、会话命名、权限、自定义指令 |
| 扩展 | Skills、MCP、钩子 |
| 设备工具（仅 Android App） | 通知事件、诊断日志 |

“常规”管理正文宽度、项目会话数量及当前客户端的缓存状态提示。会话正文宽度上限默认 950px，可填写 320～3840px；PC 优先保留所设宽度，仅在主会话区域可用空间不足时收窄，有足够留白时才按整个可视窗口居中。主题、字体、配色和背景按客户端独立保存；各端共享的设置见本节下方。快捷键只列出已经实现的编辑和菜单按键，不因展示快捷键而增加全局按键行为。

“会话实例”按真实实例选择目标，保留当前实例名称、Codex 结形标识及 Claude 橙色星芒。“显示此实例”开关由全部客户端共用，不停止任务，也不表示未接入的执行适配器已经可用。原生设置与该开关分开：Codex 提供任务清单（Todo）、记忆、子智能体、目标模式；子智能体总开关同时控制当前 CLI 的 `multi_agent` 与 `multi_agent_v2`，不能关闭 V2 后继续启用旧版。

##### 普通主按钮随面板配色

“按钮颜色”按当前客户端、主题预设及浅色/深色分别保存。色盘、HEX 输入和左侧色块显示原始色，恢复默认外观时恢复 Elver 的 `#16A34A`；派生的显示色不写回设置。规则只用于按当前调色配置了按钮色的普通主操作，例如“完成”“保存”和普通确认，以及管理页的默认类型按钮。发送／停止、危险和强调按钮、开关、导航、正文及气泡不变。

1. 取按钮紧邻的不透明主题表面色：设置页脚、普通确认弹窗使用页面底色，审批卡片使用侧栏表面色，代理设置、会话管理、远程会话的卡片与设置卡片共用实际合成的主题卡片底色，不借用输入框底色；管理页弹窗仍按实际弹窗底色计算。没有独立实色的区域用主题页面底色，不对背景图片采样，也不只看深浅模式标记。
2. 分别计算字色对按钮填充、按钮边界对相邻表面的 WCAG 对比度。可用状态的文字不低于 `4.5:1`，由填充或独立描边形成的按钮边界不低于 `3:1`。白字比填充亮、填充比面板亮时，白字对填充的动态上限为“白字对面板的对比度 ÷ 3”。以 `5:1` 为舒适目标，取目标、动态上限及最多向黑色混入 `25%` 所能达到的对比度中的最小值；混入上限用于避免把用户选定的亮色大幅压暗。
3. 白字方案使用最小压暗量；8 位颜色取整后若不满足按钮边界，可重试 `4.5:1`。仍不能同时满足两项下限时，默认态保留原始填充，优先选达标的主题控件底色作字色，否则选对比度较高的黑字或白字。悬停和按下延用现有 Codex 状态叠色比例，混入所在面板，同一按钮保持同一字色并逐态核对。任一态填充不足以建立按钮边界时，使用同一条对面板达标的描边，不改变按钮尺寸或键盘焦点样式。

Elver 深色设置页脚示例：面板 `#1E1E1E`、原始按钮色 `#16A34A`，派生显示为 `#11803A` 深绿底配 `#FFFFFF` 白字；文字对底色约 `5.03:1`，默认态按钮对面板约 `3.31:1`。更亮的面板可能保留绿色并使用黑字。工作区和管理页复用同一计算规则；未配置按钮色时同样复用中性按钮的默认、悬停和按下配色。切换主题时整组替换，不保留旧配色。

现有主题均通过本地 HEX 配置，沿用 Codex 的自定义配色路径，不引入 Codex 账号强调色来源。模式缩略图实时使用当前主题各自的明暗背景、侧栏和前景色。对比度使用 `0～100%` 的整数滑块，实时显示百分比并仅保存当前主题的当前明暗模式；滑块两端分别完整显示 `0% / 100%` 填充。背景透明度使用 `1～100%` 的整数输入框，默认 `35%`，没有背景图片或正在操作图片时禁用；按 Enter 或失焦应用，空值、小数和越界值恢复为上次有效值。HEX、字号及透明度输入中的 Escape 先恢复未确认内容，不关闭设置页；其他位置继续沿用先关闭弹层、再关闭设置的顺序。设置页布局、主题数量、字体与字号范围、自动模式的时间及 Android 光照规则、背景图片铺法保持既有功能；不新增主题导入导出。

#### 实例模型与压缩

Claude 的离开期间回顾移入该实例的常规配置，继续保留已有回顾；输入建议使用原生设置。自动压缩窗口只使用同一 WSL CLI 提供的 `--autocompact` 参数，按发行版和用户保存，应用于后续新建的远程会话；不把窗口值写入未经 CLI 确认的设置键，不重启或改写已有后台会话的启动参数。CLI 不支持的选项禁用并说明原因。

“会话实例 → 缓存与压缩”中点击“压缩提示词”行的“设置”打开弹窗，不在页面内编辑。弹窗显示该实例已保存的自定义提示词；未自定义时显示服务端返回的默认文本，已有自定义时可展开查看默认文本。Claude 没有附加默认提示词，显示“使用原生默认（无附加提示词）”。“恢复默认”只修改弹窗草稿，“保存”才写入或移除覆盖；取消不写入。提示词限制为 1～20000 个字符，保存核对打开弹窗时的实例及配置版本，失败留在弹窗并保留草稿。

Codex 写入该实例原生 `compact_prompt`；未配置时由独立 Harness 在新建、恢复及侧边会话入口应用旧管理器的默认提示词，唯一源为 `crates/elves-core/assets/default-compaction-prompt.md`。已有原生自定义提示词和提示词文件优先，正在加载的会话不强行重启。Claude 提示词保存为该实例的 Harness 偏好，只传给同一 WSL 原生 `/compact` 命令，适用于手动压缩，自动压缩保持原生规则。

压缩模型能力按实例的原生接口判断，不复用旧管理器或本地代理的全局压缩模型。当前已核对的 Codex `thread/compact/start` 只接受会话 ID，Claude CLI 也未确认独立压缩模型配置；界面明确显示“跟随会话模型”及不可单独设置的原因，不提供无效的模型保存操作。旧 `models` 设置接口保留兼容，主导航不再提供独立“模型与思考”页面。模型目录读取失败时仍展示其他已支持设置，模型写入必须等待同一实例目录恢复。

已配置模型退出目录时，思考深度不借用其他模型的能力；允许重新选择可用模型或选择“使用原生默认”以移除失效的默认模型覆盖。模型设置保存确认后同步撤销所选实例的持久目录缓存，并刷新当前实例的目录和新会话默认值；关闭设置窗口不取消该刷新，更换授权后不得刷新其他授权的数据。关闭 Ultra 时同时清除尚未提交的 Ultra 选择，其他显式等级及已有会话的原生思考深度保持原值。

Claude 的“会话实例”页提供“显示模型”：缺省显示同一实例原生 CLI 返回的全部模型，可以逐项隐藏并用“全部显示”恢复。名单按实际实例保存到 Harness，同一服务的各客户端共用；新出现的模型默认显示。设置页始终保留完整目录，隐藏项仍可重新开启；目录暂不可用时仍允许恢复全部显示，新增隐藏项须属于当前目录。

隐藏只影响会话输入区、实例默认模型及会话命名的选择列表。已有会话、已记住的新会话选择、实例默认值及已有命名任务继续保留当前模型；已隐藏的当前模型在选择器中标为只读。完整目录与模型能力继续用于判断当前模型及思考深度，隐藏不能清除能力或改写原生模型配置。展示标记随完整目录缓存，偏好保存和跨端通知后撤销旧目录缓存，迟到响应不能恢复旧的可选模型。

Codex 的 Skills、钩子列表经独立 app-server 获取；Claude 的 Skills、MCP 列表经所属 WSL CLI 获取，钩子列表读取该实例的用户级原生配置，均不依赖 Codex App。Codex 支持原生 Skill 单项启停、用户级 MCP 服务开关及钩子总开关；Claude 提供原生 Skill、MCP 列表及钩子总开关，单项管理仍保留在该 CLI。项目、插件及组织策略保持原生管理，不自动信任新钩子或内容已变化的钩子。扩展列表不向网页传递 MCP 环境变量、Header、原始命令或 Hook 提示词。

Codex 的 MCP 列表在开关旁明确显示“已开启”或“已关闭”。用户级配置未写入 `enabled` 时，按原生 CLI 默认开启展示，并在说明中保留“使用原生默认”；只读取不补写该键。状态文字和开关在 PC、手机上保持同组同排，长服务名及说明按剩余宽度换行。该状态表示所选实例的用户级配置，不代表 MCP 已连接或项目、插件、组织策略覆盖后的运行状态。兼容旧服务未提供原生默认值时，明确显示“使用原生默认”，不能把未知值显示为关闭；切换后仍沿用配置版本校验和已确认保存回执。

原生配置只修改明确支持的字段，并保留其他配置、注释、BOM、换行格式及文件权限。每次保存核对文件版本和设备写权限；WSL JSON 写入在所属用户内原子替换。缺少原生显式开关值时显示继承状态，不能伪装为关闭。保存回执不一致或结果未知时保留已确认值、禁用继续写入并要求重新读取，不自动重发。切换实例、关闭设置或更换授权后，旧读取不得更新当前页面。未接入的 Codex WSL 实例只允许查看原生常规配置，不借用本机实例执行。

### 实例额外配置

“会话实例”页增加 Codex 的 Chronicle、实验性上下文管理、本地会话存储压缩、生成记忆、使用记忆及子智能体并发上限。“记忆”是原生能力总开关，“生成记忆”和“使用记忆”分别控制后续会话的记忆生成及记忆使用指令，关闭子项不删除已有记忆。Codex 的自动压缩阈值归入“缓存与压缩”，思考摘要及默认服务档位归入该页“模型与思考”分组；默认服务档位与当前会话输入区的 Fast 选择分别按实例默认值、会话实际配置解释。

服务档位只有标准、优先（Fast）和 Flex 三种展示；已有原生 `fast` 兼容值按优先档位显示，读取或保存其他设置时不自动改写该值，避免同一优先档位出现两个设置口径。

Claude 的“会话实例”页增加同步 Claude.ai Skills、同步 Claude.ai 插件、禁用内置 Skills、跳过绕过权限确认及跟随模型参数切换。跳过确认只调整原生启动提示，不更改默认权限模式。字段是否可写必须由所属发行版、用户和可执行文件的 CLI 配置校验确认，不根据其他实例或固定版本号开放。

额外项由服务端固定登记的原生键、类型、范围及可选值生成，不提供任意 TOML、JSON、环境变量或命令编辑器。Codex 实验项先读取所选实例独立原生引擎的特性目录；已移除、已弃用、未知或读取失败时禁用写入，服务端同样拒绝提交。Claude 使用同一 WSL 用户 Home 登录环境下 CLI 的 `doctor` 和临时命令行设置覆盖核对字段类型，不生成模型请求、不修改用户配置，也不向网页返回诊断原文。

布尔项及枚举项提供“使用原生默认”；数字项留空恢复原生默认，仅接受定义范围内的安全整数。浏览器把非法数字表现为空输入时不能清除已有配置。删除覆盖只移除对应键；上下文管理从布尔形式转换为表时保留其他特性，恢复默认时不留下会重新启用特性的空表。数字输入复用既有 PC 100px、手机 82px 的容器，不增加导航层级或改变页面断点。

原生配置诊断只展示安全的既有配置值及不能编辑的原因。旧 `js_repl`、旧 `personality`、未确认的 Claude 缓存与压缩环境变量、逐模型 `effortLevel` 不作为可写设置。配置值无效时显示“配置值无效”，不伪装为“使用原生默认”或转发配置原文。环境中的压缩窗口只作诊断，远程可写入口仍只有“自动压缩窗口”，经已确认的原生 `--autocompact` 参数应用。项目授权、凭据、状态栏或通知命令、第三方连接源及 Codex App 的 `desktop.*` 偏好继续由原有入口管理。

只读诊断使用“配置值：…”标明文件中的记录，不把已移除或未确认能力的 `true` 显示为功能“已开启”。

所有新增写入沿用原配置版本、设备写权限和 WSL 原子保存检查；更新事件通知同一 Harness的各客户端。控件同时绑定编辑时的实例与配置记录，切换实例、重新读取或控件移除后，迟到的选择及数字失焦不能借用新实例或新版本保存。

悬停提示优先用一句话说明用途或点击操作；页面说明保留影响范围、保存要求和生效时机，避免展开内部状态字段或重复操作说明。确认框保留本机核对、草稿及附件处理、结果未知时禁止重复提交等关键后果。

### 会话命名

“会话命名”是同一 Harness全部 Codex、Claude 实例共用的设置，“自动命名”默认关闭。统一选择一组命名实例与模型为各实例的主会话生成标题；该选择不改变原会话的实例、模型或思考深度。命名实例与命名模型放在同一行，左侧先选命名实例、右侧再选该实例的命名模型；切换命名实例后清空旧模型并重新读取对应目录。手机也保持两个选择器同排，说明文字显示于上方。实例选择沿用现有 Codex、Claude 图标；目标或模型不可用时明确报错，不能改投其他实例或模型。

“会话命名”页点击“会话命名提示词”行的“设置”打开同款弹窗。未自定义时直接显示服务端默认文本；已有自定义时显示当前内容，可展开查看默认文本。“恢复默认”只修改草稿，“保存”仅提交提示词，不同时提交命名实例、模型等页面草稿；取消不写入，保存失败保留弹窗和草稿。默认提示词参考本机 Codex App `26.1111.2228` 的任务标题规则：按用户语言简明描述用户要做的事，区分修改和查询，沿用用户提供的简短标题，保留工单号及关键代码术语。检索摘要使用可检索的任务关键词，不写助手的结果、进度或无法执行的原因。标题长度上限默认 36 字符、范围 10～120，检索摘要最多 100 字符，提示词上限 10000 字符。旧版保存的原样默认文本随版本更新；自定义文本不覆盖。

Codex 主会话没有正式名称时，首条消息预览转为单行纯文本，最多 60 个字符（含截断省略号）；不调用模型、不把预览写成正式名称，已有正式名称和侧边标题不受影响。首条普通消息明确成功接收后在后台发起一次首次命名，不等待首轮完成；入队、结果未知、编辑、侧边会话和子智能体不触发。首次生成只提供首条用户文字，不传首轮回复或工具结果；正式标题与预览同文也按原生名称写回。既有明确名称不因开启功能而批量覆盖。

“自动更新标题”默认勾选，仅在“自动命名”开启且该会话已有自动标题后发起检查。Codex、Claude 主会话确认手动或自动上下文压缩成功后，按“标题更新间隔”累计之后的成功对话轮次，默认 5 轮，可设为 1～50 轮。压缩前、压缩所在轮、失败、中断及重复轮次不计数；只收到压缩命令回执、压缩失败或无需压缩时不重置计数。计数中再次成功压缩，以最新边界重新计数。满 N 轮最多检查一次，主题不变保留原名，检查失败也不自动重发；下次检查必须先有新的成功压缩。压缩边界及计数由服务保存，旧版累计轮次和只读加载的旧历史不补计。

手动重命名优先，并停止该会话后续的自动更新；生成期间手动改名、停用功能或更换命名配置后，迟到结果不覆盖新状态。写回前在原会话写锁内再次比较名称。跨端命名设置草稿按编辑时的版本检查冲突，不用新版本号覆盖旧草稿；实例与模型作为一组核对，另一端已经切换实例时，旧端的模型选择不能合并到新实例。生成失败保留原标题，页面显示实际失败原因；不重复发送原会话消息或自动重发结果未知的命名请求。

标题生成使用独立临时 Codex app-server，或所选 WSL 发行版、用户的 Claude CLI；不桥接 Codex App，不继承原会话任务、项目指令、工具、Hooks、MCP 或记忆。Elves 自己的命名请求经过已启用的本地代理时，保留选定命名提示词及正常的模型和协议路由，不套供应商的普通会话提示词，不向上游发送工具定义。原生返回工具或交互操作时丢弃命名结果。初始输入最多 2000 字符，主题更新只取最近 8 轮的文本，总计最多 12000 字符，不发送附件内容。命名记录、轮次去重和手动保护由服务持久保存，客户端收到成功事件后刷新侧栏及当前标题。

### 最近会话的优先事项与置顶分组

最近会话使用“优先事项”分组并沿用原有折叠键。分组标题最右侧固定显示双横向滑杆图标，上方滑块靠右、下方靠左；“清除已读会话”图标在需要时显示于其左侧。标题过长时收缩省略，操作区不换行、不压缩，清除按钮出现或消失不移动最右侧入口。没有优先事项时仍保留该标题和菜单入口。

同一 Harness 持久保存一份优先事项名单，Elves Windows 客户端、远程网页、PWA 和 Android 共用；在线端收到列表更新事件后刷新，重开及重连从服务重新读取。新建和分支成功、开始实际执行、存在待处理审批或问答、原生标记未读的主会话自动加入。侧边的执行、待处理请求和未读归到所属主会话，侧边和子智能体不单独占位置。仅打开旧会话、切换分组或筛选、恢复阅读位置和刷新目录不改变名单。

会话完成和正文已读只更新执行指示与未读蓝点，不自动移出优先事项。包括 Android 冷启动、恢复上次会话、后台转前台或网络重连，均不得把已完成且已读的条目视为应清理项。只有可写端主动点击“清除已读会话”后，服务才移出本次列表候选中已确认空闲、已读且无待处理请求的主会话；状态不明、已进入新一轮、仍未读或仍有待处理侧边的会话保留。成功移出会同步到其他设备；之后有新的执行、审批或未读时可以重新加入。清除不归档、不删除、不改真实置顶和未读状态；会话确认删除后从名单移除。旧版本仅存在单页内存的历史名单不能跨版本恢复。

点击滑杆图标打开菜单，仅提供可切换的“置顶”选项。默认不勾选；开启后选项右侧显示“√”，菜单继续保留并更新，最近视图在“优先事项”下方、日期分组上方显示“置顶”分组；再次选择则隐藏分组。该选择由同一 Harness的各客户端共用，刷新和重新打开后恢复；只读或离线时不可改写，不调用会话置顶接口，不改变会话的真实置顶状态。

“置顶”分组复用已有会话置顶列表、排序、搜索及会话实例筛选，使用最近视图的标题与项目名两行布局，并支持折叠；开启后即使没有匹配会话也保留分组标题。置顶会话不再重复显示于日期分组，仍按原规则在有待处理状态时进入“优先事项”。已有会话菜单的置顶或取消置顶结果刷新后同步反映到此分组。项目视图继续沿用原有置顶区域，不受此开关影响。切换分组显隐、清除已读和侧栏刷新均不得切换当前会话、清除输入草稿或重复计算未读角标。

### PC 会话列表菜单按钮

PC 网页和 Elves Windows 客户端在宽于 760px、支持 hover 且使用精细指针时，最近、置顶和项目下会话行的“…”按钮仅在悬停对应行时显示；选中会话或标题获得焦点不使按钮常显。键盘聚焦菜单按钮以及该菜单展开期间保留入口，执行/未读图标与按钮互斥显示。未显示的按钮不接受鼠标点击，保留原有布局和键盘可达性。手机及触屏沿用现有按钮显示与长按菜单规则。

### 会话列表右键菜单

最近、置顶和项目中的会话共用同一菜单。Elves 本机客户端按“重命名”“置顶 / 取消置顶”“独立窗口打开”“复制”“打开方式”“删除会话”固定排序；独立窗口项仅在可信本机工作区且窗口支持时显示。远程 PC、手机网页、PWA 和 Android 都不显示“独立窗口打开”和“打开方式”，不保留禁用占位。“复制”之前和“删除会话”之前显示分隔线。右键、长按及“…”入口使用同一内容；删除沿用原有确认和结果待核对流程。

“文件”和“变更”的右键独立预览同样只供 Elves 本机客户端使用，不回退为远程浏览器弹窗。远程旧会话窗口链接按普通会话打开，独立文件预览地址不可用；页面内的文件、变更预览和右侧标签不受影响。

“复制”子菜单依次为“复制工作路径”“复制会话 ID”。工作路径只取该行明确提供的 `cwd`；会话 ID 优先取后端提供的 `nativeId`，没有时使用该行的会话 ID。实际 WSL 实例必须添加真实发行版名称及一个空格，例如 `claude-us xxxxx`；本机实例不能仅凭路径位于 WSL 目录而添加发行版。路径或 ID 缺失时对应项禁用，已确认属于 WSL 却缺少发行版名称时不复制不完整 ID。

“打开方式”子菜单复用 Open in 的服务端应用检测、顺序、图标、实例限制及幂等启动回执，按被右键会话的身份读取和启动，不切换当前聊天。该入口仅在服务端确认 `transport: "desktop"`、声明 `workspaceOpenIn` 能力且设备可写时可用；顶部 Open in 按钮还要求 Windows 独立客户端原生环境。远程入口不声明此能力，不能通过原生桥标记、设备名称或屏幕尺寸取得。没有应用时显示“未检测到可用应用”，读取失败提供原地重试，更换授权、会话实例或删除状态后不派发旧操作。应用启动后未确认前台显示时保留原有提示和回执，不重复启动。

两个子菜单支持鼠标悬停、点击、触摸及键盘：右方向键进入子菜单，左方向键或 Esc 返回父菜单，上下方向键和 Home / End 选择，Tab 关闭。子菜单优先向右、空间不足时向左，四边至少保留 8px；窄屏无法并排时重叠展开并显示返回入口。侧栏刷新保留父、子弹层和读取状态，只换绑同一会话的新行；会话或对应操作失效时关闭菜单。

### 正文文件引用右键菜单

会话正文仅对明确带目录信息的文件路径提供文件菜单。支持 `src/app.ts`、`./README.md`、`src\app.ts` 等相对路径，以及 Windows、Linux 和 `file:///` 绝对路径；相对路径以该会话工作目录为起点，即使会话位于 Git 仓库子目录，也不能改按 Git 根目录解析。`README.md`、`app.ts:12` 等仅有文件名的普通文字、行内代码或 Markdown 链接保持普通内容，不绑定文件右键、长按或点击操作。Markdown 链接目标明确包含路径时可作为文件引用，即使显示标签只有文件名。

能够触发文件右键菜单的正文引用，左键单击默认执行同一菜单中的“打开文件”，保留路径、行号及当前会话和授权校验；禁用时不绕过菜单限制。右键及长按继续打开菜单，长按或拖动产生的合成点击不打开文件，之后的新一次正常点击立即生效。

Elves 本机客户端的正文文件菜单固定依次为“打开文件”“浏览器打开”“在 File Explorer 打开”“打开方式”“复制路径”。远程 PC、手机网页、PWA 和 Android 仅保留“打开文件”“浏览器打开”“复制路径”，移除 Explorer 和打开方式，不保留禁用占位。打开文件沿用文件预览及行号定位；“浏览器打开”在 Android 使用内置浏览器读取已授权的原会话文件地址，其他端由已授权服务调用系统默认浏览器打开原文件，不按窗口宽度改变方式，也不使用文件扩展名关联的默认编辑器。File Explorer 打开所在目录并选中该文件；打开方式复用 Open in 实际检测到的应用、图标、顺序和实例限制，编辑器接收所选文件路径，普通终端进入文件所在目录，GitHub Desktop 打开所属工作区，WSL 保留原会话 attach / resume 规则。“复制路径”复制引用路径，不附加行号；相对路径仍复制其相对形式。

PC 网页和 Elves Windows 客户端的侧边会话正文中，左键文件引用或选择“打开文件”后，在外层右侧标签栏新建并选中文件标签，不在侧边内容区打开整页预览。原侧边页面、输入草稿和阅读位置保持；切回直接复用。同一来源会话的同一路径复用文件标签并更新行号，不同来源的同名路径分别保留。文件读取固定使用来源侧边身份及原授权，隐藏或关闭的侧边、其他主会话和旧授权不能触发新标签；子智能体共用相同的文件转交规则。手机、Android 及普通整页关联会话继续沿用原页预览，浏览器打开、Explorer、打开方式和复制路径保持各自入口。

所有“在 File Explorer 打开”入口复用 Open in 的彩色 File Explorer 应用图标，使用同一图形及深浅主题配色，不再使用灰色线框文件夹。

“在 File Explorer 打开”及“打开方式 → File Explorer”均以已校验原文件的完整 Shell 身份打开所在目录并选中文件，保留中文、空格和逗号等路径字符；文件协议的正斜杠在原生边界转换为 Windows 分隔符，不通过 `/select` 命令行字符串定位。文件不存在、路径不允许或原生定位失败时显示错误，不回退到“文档”、工作区根目录或其他默认目录。

缓存正文先显示、会话详情稍后返回时，文件引用只在渲染时绑定所属会话与授权；打开菜单或点击链接时读取该会话的完整工作区身份，不能因首次渲染时详情尚未返回而永久置灰，也不要求重绘正文。每次打开的菜单固定当时的路径和身份；会话、授权、工作目录或实例发生变化后，旧菜单不得继续操作。

文件打开请求与持久回执按会话、应用和文件路径分别保存，不改写工作区首选应用；旧授权、会话或实例失效后不得派发旧操作。服务端沿用文件预览的项目及所属引擎范围、WSL 映射、路径越界、符号链接和重解析点检查，实际启动前再次核对原文件，不根据网页路径开放任意本机文件。应用未安装、文件缺失或校验失败时显示实际错误，不降级为打开整个工作区或浏览器。

正文右键及长按菜单以触发坐标定位，复用会话列表二级菜单的键盘和边缘避让；主菜单宽度至少 240px，并随文字宽度增长至视口允许范围，打开方式子菜单沿用 178px。点击外部、Esc、失焦或窗口变化可收起菜单，滚动应用列表本身不关闭。文件预览页内部引用沿用原操作入口。

### 会话视频预览

会话正文的视频预览与图片共用一层深色半透明遮罩。播放器底板透明，竖屏视频两侧的留白与弹窗外围连续，不额外铺底。预览按整个可视页面居中，沿用 `90vw` 宽度和 `80dvh` 高度上限；关闭按钮仍在弹窗右上角。

画面等比适配。播放／暂停、进度条及时间放在实际画面正下方，整组与画面同宽，窄画面可换行，不按弹窗宽度拉伸。播放前使用封面比例，封面尺寸未知时先按 `16:9` 占位；取得实际视频尺寸后按实际比例重新对齐，窗口尺寸变化时同步重算。只在用户点击播放后加载视频，关闭时停止加载。

### Codex 会话被其他应用持有

当独立服务确认当前 Codex 会话由其他原生进程持有写入锁时，在原输入框位置显示锁图标、标题“在另一个应用中打开”和说明“请先在那边关闭会话，才能在这里继续。”。提示复用原输入区的会话底部容器、宽度及边距，原位替换，不另设页面顶部提示或悬浮层。隐藏整组输入框及其工具栏，保留原编辑器节点、草稿、附件和排队消息；本机客户端、网页、PWA 和 Android 共用此规则。只提供右侧“重试”，不提供“创建聊天分叉”按钮。仍可阅读历史、切换会话或新建其他聊天。

占用检查只读取实际独立引擎所属 Codex Home 的原生 OS 写入锁，并排除本服务同一连接代次持有的会话；锁文件存在但未被加锁不算占用。不为检查恢复会话、抢占写入锁、删除锁文件或调用 Codex App。重试仅重新读取会话状态，检查期间显示进行状态；锁仍在时保留提示，确认释放后恢复原编辑器，不自动发送草稿或重放写操作。切换会话、授权或连接代次后，迟到重试不抢焦点、不影响新页面。原生写操作继续校验写入锁，读取快照不能代替派发时的校验。

### 会话编辑区本机文件和文件夹

会话编辑区左侧“+”菜单从上到下依次为“压缩”“目标”“文件和文件夹”“图片”。各项保留原有的显示和可用条件；隐藏某项时，其余项目的相对顺序不变。Elves Windows 客户端点击“文件和文件夹”直接打开一个系统选择窗口，不再展示二级菜单。可在同一列表中多选文件和文件夹，通过“添加所选项”确认；双击文件夹仍进入目录，取消不添加附件。新版网页资源配合旧版客户端时仍可直接打开原文件选择窗口，提示通过拖放或粘贴添加文件夹，更新客户端后才支持同窗选择。普通浏览器、手机网页和 Android 不显示原生选择器；可以接收浏览器在本次拖放或粘贴中提供的文件、目录对象，不增加读取任意本机路径的权限。

文件和文件夹预览沿用现有图片的 40×40 CSS 像素框，居中分别显示文件、文件夹图标；名称显示在框下方，单行超长省略，悬停可查看全名，右上角保留移除按钮。图片继续显示原缩略图。文件夹保留子目录、空目录和文件内容，不能只发送客户端本机路径。

图片、文件、文件夹可混合拖入会话编辑区；拖入普通文字时保持原文字行为，不将 URL 或文字路径自动读取成附件。拖放回调内立即捕获浏览器授予的 File、目录入口或 handle，异步读取不能在事件结束后重新访问受保护的 DataTransfer。文件夹逐页读到结束，保留子目录和空目录；浏览器未提供或未允许读取的目录明确提示失败，不根据文件夹名称猜测路径。

在文件资源管理器中 Ctrl+C 复制文件、文件夹或混合选项后，可在独立客户端输入框 Ctrl+V 添加；无 DOM paste 的目录由原有 CF_HDROP 入口补读一次。浏览器粘贴只读取剪贴板实际提供的文件及目录对象，系统文件夹粘贴能否提供目录内容取决于浏览器；不为补齐此能力扫描本机目录。普通文字和截图粘贴保持可用。原生端仍只处理系统选择器结果或 CF_HDROP，不接收网页传入的本机路径；逐次核对服务、前台窗口和会话页来源，预览页及内置连接页不能调用。选择和粘贴的前台校验以发起操作的 Windows 顶层窗口为准：键盘焦点在该窗口的 WebView 输入区时仍可添加，其他窗口在前台时不得接收附件。

每条消息最多选择 16 个文件/文件夹，最多包含 512 个文件和目录项、32 层目录，文件内容合计不超过 12 MiB；图片使用独立的[数量与容量限制](#图片输入格式)。遇到超限、不可读取或无效名称时明确显示失败，保留已有输入和附件，不静默跳过文件。选取或粘贴期间切换会话、项目或授权后丢弃迟到结果。

原生读取继续拒绝符号链接、重解析点及特殊文件；网页只接收浏览器已授予的对象，发送端统一校验名称、相对路径、层级、大小和内容编码，不传递本机真实路径。普通文件及目录遍历设 30 秒读取上限，失败的混合批次不插入部分内容，保留原有附件。发送文件只要求服务声明支持附件，不以是否安装原生选择器作为浏览器发送条件。

附件随草稿及失败恢复记录保存；发送前由独立服务校验目录结构、内容大小及编码，写入设备和请求隔离的附件目录，再向原生引擎提供实际可读路径。Claude 路径按所属发行版、用户转换，不借用其他 WSL。发送、队列和未知回执沿用原有可靠提交规则，不提前显示成功，也不因结果未知自动重发。

### 图片输入格式

图片入口、拖放和粘贴共用图片识别。除 PNG、JPEG、GIF、WebP 外，增加 BMP、AVIF、静态 SVG、ICO/CUR；兼容 APNG、JFIF、JPE 及常见 JPEG MIME 别名。原有四种发送格式保留原内容，新增格式经当前客户端实际解码、检查尺寸后转换为 PNG，不只修改 MIME 或扩展名。原始名称保留，图片预览、草稿和队列记录使用实际生成的发送格式。

Codex 和 Claude 每条消息最多 8 张图片，编辑待发消息时保留的旧图和新图合并计数。单张输入及转换结果均不超过 5 MiB，总图像内容不超过 12 MiB；最大边 16384 像素、总像素不超过 100000000。转换后再次检查实际字节数和 PNG 签名，超限或无法解码时说明原因并保留已有附件；不把未解码的文件标成已添加图片。SVG 不执行脚本、动态内容、外部文件及网络引用，原文不插入页面 DOM，静态内容由图片解码器栅格化。

Windows 原生剪贴板混合项中的顶层图片进入图片通道，文件夹中的内容保持原目录结构。Android 原生有序图片选择器继续接收单一 `image/*`，桌面选择器补充常被 MIME 过滤遗漏的图片扩展名，不因扩展格式而改变既有原生选择器顺序和回退流程。

### 会话编辑区斜杠命令

Codex 和 Claude 会话编辑区的 `/` 菜单均提供“提示词优化”入口，支持按“提示词优化”“优化提示词”、`prompt-optimize`、`optimize` 的连续片段筛选。入口与工具栏优化按钮共用可用状态，不依赖 Claude 原生压缩或目标能力；只读、输入禁用、执行中、停止中或等待回执时保持不可选。鼠标点击及 Enter/Tab 键盘选择均只移除当前 `/` 查询文本，保留其余提示词、Skill 和附件，然后调用现有独立提示词优化流程，不直接发送消息。

### 分支到新聊天

Codex 持久主会话的已结束回复下方提供 `⋯`“更多操作”，悬停、键盘聚焦及菜单展开时显示；触屏始终显示。菜单提供“分支到新聊天”，复制该回复所属完整原生轮次及之前历史，排除之后轮次；执行中的目标轮次不提供入口。输入框 `/` 菜单在“压缩”下方提供同名命令，支持 `/fork` 或中文筛选，保留旧名称作为搜索词，从当前最新进度分支，沿用空文字编辑框的调用方式；不自动发送旧问题、草稿或附件。

两个入口只使用服务端核对的源会话当前工作目录，不提供 worktree 或目的地选择，不回滚或复制工作区文件；分支通过独立 CLI / app-server 的持久 `thread/fork` 创建，原会话保持原样。新会话使用递增编号标题并进入普通会话列表，正文提供来源聊天链接；创建后打开新会话并聚焦编辑框，期间已主动切换会话或授权时不抢回页面。创建成功后的标题或本地元数据同步失败只提示附加错误，不重复创建；超时、断网、刷新后保留原回执，仅查询原请求。

侧边会话不开放分支、嵌套侧边或主会话历史编辑，回复下方的分支 `⋯` 按钮及 `/` 菜单分支项均直接移除，服务端同样拒绝该操作。临时侧边输入区“+”及 `/` 菜单直接移除“目标”；持久侧边保留原生目标能力，是否向模型提供目标工具仍按所属实例的原生配置决定。子智能体、只读设备及未声明分支能力的其他实例不开放分支入口。左侧普通主会话列表中的会话仍可在打开后使用上述两个入口，不新增会话列表右键分支项。

### 侧边会话生命周期

临时侧边创建时只在该原生分支覆盖 `features.goals=false`，移除 `get_goal`、`create_goal`、`update_goal` 工具，不改写主会话或实例配置。Plan/Default 从源会话最近仍有效的非独立压缩轮次及其原生记录读取，在创建时保存；没有实际轮次的新会话使用 Default，已有轮次却无法确认模式时明确失败，不静默降级。后续普通发送、排队续发及压缩后的新轮次都显式传递该模式，并同步使用侧边自己的当前模型和思考深度；保留源模式的自定义指令，父会话后续模式变化及客户端载荷不能覆盖已有侧边的模式。

持久侧边使用独立原生 `thread/fork(attachToSource:true, ephemeral:false)`，父子关系以 `attachedToThreadId` 为准，历史读取只展示侧边自身消息，父历史只作为模型参考上下文。正文及关联由原生保存，Harness 仅保存创建权限、Plan/Default 和初始化状态；重启后通过原生关联列表重新发现，读取不自动恢复执行。首次发送前即重启也须沿用创建快照；缺少已确认快照或边界初始化未完成时仅支持查看，不能借用父会话或后来变化的全局权限继续发送。持久侧边不作为独立主会话进入最近、置顶、项目、任务栏角标或主会话自动命名；执行、待处理请求和未读仍聚合到所属主会话。首条成功接收的文字取前 15 个 Unicode 码点作为原生标题，后续消息不覆盖。

关闭持久侧边标签只卸载页面，保留历史、队列及执行状态，可从所属主会话菜单重新打开；不能显示临时侧边不可恢复的确认文案，不能自动停止其任务。服务重启保留持久队列和未知回执，沿用普通持久会话的暂停、核对及幂等保护，不因恢复或再次打开自动重发。

原生侧边 ID 在创建回执前就可能出现在关联列表；边界注入、创建快照、模型设置及初始化确认必须与该侧边的写操作共用会话锁。初始化失败、权限或 Plan/Default 快照损坏时保持只读，不使用后来的全局权限补齐，也不能因并发删除而恢复已删除记录。

单个持久侧边读取失败不得阻断主会话、临时侧边和其他关联会话。服务返回 `sideThreadsComplete:false` 及实际失败原因，菜单保留已知持久侧边行并提示读取不完整；仅完整列表或明确删除事实可移除原标签关系，不将缺失行当作已关闭。关闭回执按原授权及原主会话定位标签，即使用户已切换主会话，也只卸载原所属标签，不抢焦点或切换当前页面。

侧边正文不设置累计字节上限，也不因未关闭侧边数量达到 16 个而拒绝创建；不得因超过旧 16 MiB 阈值截断历史、拒绝补读或停止继续发送。待发送队列和附件继续使用其独立准入规则，不作为已接收正文的容量限制。

侧边加载资源采用闲置退订：每 30 秒检查一次，只处理 Harness 当前原生进程实际加载的侧边。任一设备/页面正在查看，或存在执行、压缩、活动目标、审批/问答、任意待发或暂停队列、队列编辑、未知发送/删除结果及初始化未完成时均保留。安全空闲且无查看满 3 小时后退订；未活动的持久侧边加载数超过 10 个时，优先退订较早的超出项，临时侧边不按该数量规则提前终止。所有检查与实际发送共用会话写锁，派发前再次核对原生身份、权限快照、目标与真实执行状态；不自动中断任务、不删除历史、不恢复或接管其他原生客户端的线程。

页面仅在实际可见时每 30 秒报告查看租约，服务端租约 90 秒；按设备授权及独立页面区分，多端/多标签任一有效查看都保留。隐藏 iframe、页面后台、离页和切换会话停止原查看租约，乱序旧消息不得覆盖新状态；普通历史、目录及未读轮询不算有人查看。心跳失联由租约到期结束查看保护，后台回收不为此启动或重连引擎。

持久侧边退订后保留原生历史、父关联和创建快照，读取仍不恢复执行，下一次明确发送才按原会话 ID 恢复。临时侧边闲置退订后保留已接收的只读正文，显示“临时侧边已闲置退订”及无法恢复执行的说明，由用户新建侧边继续；不自动转换为持久会话。退订失败或结果未知时不报告释放成功、不自动重放退订，页面保留正文并说明结果待核对，阻止新任务越过未确认退订继续执行；后续明确原生卸载事实或服务重新建立连接后再更新。

### Codex 历史消息编辑

Codex 主会话中，每个历史轮次的原始用户消息均可从原有编辑入口修改并重新发送，包括翻页加载的旧轮次。进入编辑、修改文字和取消均不改写历史；编辑区明确提示：提交会移除被编辑轮次及其之后的会话历史，工作区已修改的文件不会回退。引导消息、只读子智能体和临时侧边会话不因此开放历史编辑。

提交通过当前实例的独立 Codex CLI / app-server 完成：恢复原生会话写入归属，分页定位原轮次并重新核对编辑开始时的历史头，再调用 `thread/revert(beforeTurnId)`，最后以修改后的文字、原消息附件及 Skill 启动新轮次。不能只查最后一轮，也不能依赖 `thread/read(includeTurns)` 获取分页历史。原轮次之前的历史和计划保留，被移除轮次的计划和压缩记录不得由迟到缓存补回。

执行中、压缩中、有排队消息、未完成队列编辑、待处理审批或发送结果未确认时禁止历史回退。其他端新增消息或回退历史后，旧编辑必须重新核对；服务端在会话写锁内直读校验，网页显示状态不能代替校验。提交前持久保存修改后的文字，失败后沿用现有恢复入口且不覆盖普通草稿；成功重发保留原消息的附件及 Skill。重发沿用稳定的客户端消息 ID；回退或发送结果未知时保留原回执，不自动再次回退或重发，仅以同一新消息的原生接收证据确认成功。

### 会话权限菜单

Codex 和 Claude 的会话权限入口只显示权限图标和当前模式，不显示右侧下拉箭头；点击仍打开原权限菜单，其他 Select 控件的箭头保持不变。权限菜单的标题、选项、说明及链接文字统一继承当前设置的 `--font-size`，不再使用独立固定字号。Codex 的“了解更多”紧随“应如何批准 Codex 操作？”显示，底部不再重复出现。Claude 不显示“模式”标题，权限说明及待生效原因均位于选项列表顶部，底部不重复显示；其他 Select 弹层继续沿用原定位。

Claude 仅在存在对应的权限切换记录、该记录仍处于等待状态且原生权限尚未达到目标模式时显示待生效说明。仅凭选择值与原生值不同不显示；原生权限已经等于目标模式时，即使仍有旧等待记录也不显示。说明分别标明已选择的目标权限和当前原生权限，并保留原生返回的具体等待原因；其他情况只显示常规的“绕过权限”支持说明。

### Windows 任务栏未读角标

Elves Windows 客户端任务栏角标与会话栏实际显示为未读的主会话数量一致，不按消息或轮次累加。会话处于执行中时不计未读，即使原未读标记仍然保留；执行结束且未读标记仍存在时恢复计数。执行状态与会话行共用判断：`priority.active` 的布尔值优先，缺失时读取 `status` 的 `active / inProgress`，关联侧边执行状态同样排除；等待回复不按未读计数。

最近、置顶和项目中重复出现的主会话只算一次，侧边子会话、子代理及归档会话不单独计数。搜索、折叠和快捷筛选不改变总数，读完后减少，为零时清除，超过 99 仅在图标上显示 `99+`。

### 会话活动耗时

远程会话渲染区的活动摘要从“已处理 1秒”开始计时；已知耗时不足 1 秒（含 0 毫秒）时，统一显示 1 秒，完成后的“用时”摘要沿用同一下限，不显示“<1秒”。该下限仅用于展示，不改写原始耗时；缺少有效时间或等待启动时，保留原有状态提示。

### 会话任务清单恢复

任务清单只来自原生计划，不根据正文或执行时间生成。Codex 按轮次显示；独立服务收到计划更新后保留该会话、该轮次的最新快照，新开页面、刷新及切回会话时通过历史响应补齐，不等待模型再次更新计划。缺少计划字段不代表清空，明确空数组才清空；迟到历史和旧版本计划不能覆盖新更新。编辑回退只撤销被移除轮次的计划，删除会话释放全部计划；侧边清单只来自自身事件，过期后随只读正文保留，关闭后释放。

Codex 快照仅属于当前独立引擎运行代次；服务或引擎重建后，不承诺恢复之前未持久化的计划，也不把旧浏览器缓存当作当前计划。其他客户端的任务若没有被本服务收到，不通过 Codex App 桥接补齐。

Claude 清单属于整个会话，始终显示完整有效历史中的最新快照，并放在正文末尾。首屏和旧页均额外返回该快照，不受每页 10 轮或实时通知轮次窗口影响；明确清空后，后续轮次不得从旧任务种子恢复已删除清单。切换会话或授权时隔离状态，迟到读取不能覆盖更新或回退后的清单。

### 上下文压缩详情

Codex 和 Claude 的正文压缩事件使用跟随主题的分行提示，依次显示状态说明、压缩模型、压缩前后 Token、缩减比例及用时。提示复用输入区的 200ms 悬停延迟、键盘聚焦、上下避让与至少 8px 视口边距，窄屏换行，不改变正文事件行的大小。用时达到一分钟时显示分钟及剩余秒数，保留原生毫秒精度。

点击或轻触正文压缩事件的信息图标，或聚焦后按 Enter / Space，立即打开同一份详情；展开后移开鼠标不关闭。再次激活图标、点击外部、按 Esc 或离开当前事件时收起。Esc 只关闭本次展开的详情，不同时退出当前会话页面。其他正文事件或输入区提示保持原交互。

压缩模型只取该次原生压缩条目或其压缩元数据的显式型号，不取当前输入区模型、实例默认模型、压缩前后普通消息的型号，也不根据代理配置猜测。原生没有提供时明确显示“原生未提供”；无需执行压缩时显示“未执行压缩”。Token 和用时只展示有效的已返回数值；缩减比例仅在压缩前大于零且压缩后不大于压缩前时计算。同一条压缩的旧快照缺少模型字段时保留已确认值，切换会话不得串用。

### 会话 Token 统计 hover

远程会话输入区左下 Token 统计的 hover 使用一行描述，按“首 Token 时间 · 本轮耗时 · 缓存命中率”的顺序，仅显示当前轮次已经取得的原生实测字段。字段尚未返回时整项省略，不显示 `—`；三项均未返回，或新轮次尚未取得统计时，不显示 hover。底栏原有速度、步数和 Token 汇总保持不变。

本轮耗时与目标运行时间共用 `d/h/m/s` 格式，按整数秒展示，例如 `5876.39 秒` 显示为 `1h37m56s`，`61 秒` 显示为 `1m1s`。首 Token 时间仍按毫秒或小数秒展示。

首 Token 时间从轮次开始计算到首个真实模型流式输出，正文、思考或工具参数均可作为首个输出，工具执行结果不计入；不得用完整回复到达时间代替或估算。缓存命中率为本轮各次模型调用的缓存读取 Token 总量除以输入 Token 总量，任一相关字段缺失时不输出该比例。

侧边会话（含手机整页）在输入框下方沿用相同的速度、本轮步数与用量、总量、缓存倒计时和 hover，只接受侧边自身的 `codex-side` 数据。临时侧边按自己的 `threadId / turnId` 接收原生 `thread/tokenUsage/updated`，只累加侧边自身请求的 `last` 实测用量；含父历史的 `total` 只用于判重及检查缺口，不作为展示值。继承快照和压缩估算不能记账；用量不完整时隐藏无法确认的合计。上下文环仍按原口径展示，不从环中取数补齐底栏。

持久侧边重启后从其自身原生 rollout 的模型调用用量恢复统计，只累加侧边自身调用，不能直接采用含父参考上下文累计量的 `total_token_usage`。首次只尾读到部分历史时隐藏无法确认的总量；不读取父 rollout 补齐，也不把暂缺字段估算为零。

“总”之后显示缓存剩余时间，例如“总 5m　缓存 55分”。剩余至少一分钟时只显示整数分钟，不足一分钟时显示秒；到期或无法判断时隐藏缓存项。倒计时由本地计时器更新，不增加统计请求，不因轮询、历史重读或页面重绘续期；切换会话、授权、隐藏页面及离线时取消旧计时器。主会话和侧边分别使用自己的模型与缓存观察，不能混用父会话统计。

缓存时长优先采用响应缓存写入明细，其次采用实际出站请求的 TTL，再采用有依据的模型默认规则。Claude 从所属 WSL 原生 CLI 的会话用量读取 `5m / 1h` 明细，不能仅凭登录账号推断为一小时；混合缓存取最先到期的一段。OpenAI 支持 `30m / 12h`，12h 缓存命中只保留原截止时间或本次读取后 30 分钟中的较晚值，不重新给予 12 小时；`in_memory` 和 `24h` 分别按 5 分钟、30 分钟估算活动窗口，不能把保留上限当作确定剩余寿命。缺少请求配置时，GPT-5.6 及之后默认按 30 分钟，旧 GPT 和 Claude 按保守的 5 分钟窗口估算；其他未确认模型不套用统一时长。缓存项提示须说明估算依据及实际可用性由上游决定，原 Token hover 的实测字段保持不变。

侧边过期后保留最后已经取得的统计，主动关闭时随正文释放；切换主会话或其他侧边时取消旧读取，迟到回执不得覆盖当前侧边。原生只读子代理仍不显示该输入区统计。

### Claude 账号邮箱脱敏

Claude 账号信息弹层的眼睛图标紧跟邮箱文本显示，订阅等级仍位于账号行右侧。邮箱默认脱敏，`@` 前只显示前 3 个字符并固定追加 `***`，域名保持完整，例如 `sarahconnor@meiguoup.com` 显示为 `sar***@meiguoup.com`。点击眼睛在当前弹层内切换明文与脱敏，不持久化明文选择；关闭再打开或账号发生变化时恢复脱敏。没有有效邮箱时保持“账号信息”，不显示眼睛。

### 弹出菜单的水平展开方向

普通按钮菜单、Select、模型菜单等采用通用定位规则的菜单，按**可视区域左侧 65%、右侧 35%**划分展开方向。会话主菜单采用下方主会话区域内的固定间距规则，Open in 保留固定向左展开。

以触发入口的水平中心确定所属区域。使用实际可视区域的左边界和宽度计算，包含缩放、平移产生的偏移：

```text
入口中心 = (入口左边缘 + 入口右边缘) / 2
方向分界 = 可视区域左边界 + 可视区域宽度 × 0.65
```

| 入口中心位置 | 首选展开方向 | 水平对齐 |
| --- | --- | --- |
| 小于方向分界，即左侧 65% 范围内 | 向右展开 | 菜单左边缘对齐入口左边缘 |
| 大于或等于方向分界，即最右侧 35% 范围内 | 向左展开 | 菜单右边缘对齐入口右边缘 |

恰好位于 65% 分界的入口归入右侧 35%。例如，可视区域宽 1000px、左边界为 0 时，中心位于 600px 的入口向右展开，中心位于 650px 或 900px 的入口向左展开。

先按上述分界确定首选对齐，再沿用现有的边缘避让，通用菜单与可视区域边缘至少保留 8px。重新定位时使用最新的入口和可视区域坐标；窗口缩放、可视区域平移或侧栏、面板布局变化不能沿用旧坐标。

本规则只调整水平展开方向。菜单的宽度、高度、上下展开条件、与入口的垂直间隔及滚动行为继续遵循各控件的现有规则。手机会话菜单已有的“宽度取视口 65%”属于尺寸约定，与本条方向分界分别维护。

### 已有特殊定位规则

已有明确固定方向、固定对齐或指定坐标的菜单保留原规则，不因通用分界调整而批量覆盖。

### 实现与验收

工作区的通用水平定位统一使用 `assets/harness/ui/position.js` 中的 `menuHorizontalLeft`。Select、普通按钮菜单和模型菜单复用同一计算，避免各自保留旧的 50% 分界。会话主菜单在 `assets/harness/session-menu.js` 中读取 `.conversation` 的实际边界及 `.conversation-header` 的底边，以“标题栏底边 + 20px”“主会话右边缘 - 20px - 菜单宽度”定位，并持续跟踪这些边界及可视视口。本机客户端 Open in 在 `assets/harness/features/session/open-in.js` 中按“按钮组右边缘减菜单宽度”固定向左定位，并通过通用弹层的 `popupFit` 回调统一处理首次打开、列表刷新和全局重定位。

调整或验收相关菜单时，核对以下场景：

- 入口中心位于可视区域 50%～65% 之间时，向右展开。
- 入口中心位于 65% 分界之前、恰好位于分界及越过分界时，分别采用正确方向。
- 可视区域存在水平偏移，或窗口、侧栏、右侧面板改变布局后，按最新坐标重新判断。
- 左右边缘避让、现有宽高及上下展开规则保持有效，已有特殊定位菜单继续沿用例外。
- 会话主菜单首次打开、侧边标签展开/收起、分隔线拖动、左侧栏开关、窗口缩放及标题栏高度变化后，始终位于主会话区域内，距标题栏底部与右边缘各 20px；即使按钮坐标不变而会话边界变化，也必须更新位置。PC 默认宽 300px，手机短边不足 600px 时默认宽为可视视口的 65%，空间不足时缩小宽度以保留会话两侧各 20px。
- 本机客户端 Open in 的入口位于 65% 分界任一侧时均向左展开；应用列表加载或刷新、页面滚动、窗口缩放及右侧面板变化后，继续右对齐按钮组并保留原有尺寸、上下避让和边缘留白。

### 压缩期间的排队消息

主会话和临时侧边会话执行过程中手动触发“压缩”时，将“压缩上下文”作为独立操作加入当前待执行队列，与普通消息按队列顺序执行，不打断当前任务。空闲时仍直接触发压缩；异步准备后由服务端重新核对实际执行状态。排队压缩可删除及调整顺序，不支持取回编辑或在执行中引导；任务正常结束后执行压缩，压缩完成后再续发后续消息。中断、失败、授权撤销或结果未知时保持原有暂停与核对规则，不自动重发；空闲后可手动重试原队列项。确认入队不等于压缩已开始，不锁定普通输入，不在正文提前插入压缩事件。

压缩准入期间原任务恰好结束时重新读取状态，已空闲则直接压缩；原生仍报告执行中却无法确认轮次时明确返回“未提交”，不保存无法继续执行的队列项。压缩派发失败或结果未知时，后续队列保持暂停，删除失败项不能自动恢复后续消息。Claude 每次实际派发使用独立且预先持久保存的原生命令 ID，只有同次原生执行或完成证据才能确认未知结果，发送前的 `pending` 意图及旧尝试的迟到结果均不能作为成功依据。用户在新授权下明确重试后，该项后续派发绑定本次有效授权，原生暂缓时也不能回到已撤销的旧设备授权。网页无法保存回执时不提交且不保留压缩锁；已确认回执后的读取失败只提示读取失败，不回退为送达未知。更换授权后旧回执不修改当前模型选择，明确失败的回执保留原模型选择，上一轮压缩的迟到完成事件不解除新请求的锁定。

主会话和临时侧边会话在已确认压缩期间均可排队发送、取回并编辑排队消息、提交修改、删除及调整队列顺序。压缩状态只禁用队列引导及立即执行，不禁用队列菜单、编辑框或附件；草稿恢复仍保留已有输入、设备授权及待确认回执保护。

侧边新消息只在服务端确认正在执行或压缩时入队，不能仅因客户端携带旧 `queueOnly` 标记让空闲消息滞留。压缩期间不向原生派发队列消息；正常完成后依次续发，失败、中断、授权撤销或结果未知时沿用原有暂停及核对规则，不自动重发。

### 子会话的侧边标签

PC 网页和 Elves Windows 客户端从会话菜单的子智能体列表、已完成列表或正文子智能体入口打开子会话时，使用与侧边会话相同的右侧标签面板。主会话选中项、输入草稿、正文及历史导航保持原样；重复打开同一子智能体复用已有标签，不重载独立页面。子智能体保留原生只读限制，不能因进入标签而开放发送、编辑或审批。

子智能体、侧边会话、文件和变更可同时保留标签，按主会话保存选中项、显隐和阅读状态；切换主会话后切回恢复原标签，授权变化清理全部标签。关闭标签只卸载页面。手机和 Android 继续使用原有关联会话整页。

从菜单打开、创建成功或主动点击侧边标签时，等该侧边的输入框可编辑后默认聚焦，保留草稿和正文滚动。重新展开已有侧边的面板也可直接续写；仅恢复布局、后台刷新、键盘在标签间移动、只读或已过期时不抢焦点。等待侧边加载期间另有输入或点击、切走标签或变更授权时取消旧的聚焦请求。

侧边会话未读时，在标签标题左侧以 6px 蓝色圆点替换原图标，保留 14px 图标占位及标题文字；蓝点优先于执行旋转图标。已读回执成功后恢复当前执行图标或普通图标，隐藏标签和其他主会话下的标签继续保留各自未读状态，不能仅因父页面选中标签就清除。

主会话及侧边会话存在待处理审批或问答时均显示未读提醒，不依赖执行结束或下一次目录刷新。查看正文或确认正文已读不能清除待处理请求的提醒；请求处理完成后按剩余请求、正文未读和实际执行状态恢复显示。侧边标签不单独增加 Windows 任务栏角标，等待回复仍沿用既有角标排除规则。

### 删除带侧边会话的主会话

删除 Codex 主会话时，只有全部关联侧边均未处于执行状态才允许继续。任一侧边正在执行时直接拒绝，提示“侧边会话执行中，无法删除”，不得由删除流程自动中断该侧边，也不得派发主会话删除。服务在删除预检及取得各侧边锁后分别核对，避免预检后的新发送绕过限制。

全部侧边空闲后，独立远程服务逐个暂停并清理临时侧边的待发队列，通过原生 `thread/unsubscribe` 确认临时侧边关闭，再执行主会话的原生 `thread/delete`，不要求用户先手动关闭空闲侧边。任一临时侧边关闭失败时不得派发主会话删除，并明确提示主会话未删除；主会话执行中、状态未知、压缩、待处理交互或写入结果待核对等既有保护保持不变。原生只读子智能体仍由主会话删除流程处理，不能当作服务侧边单独退订。确认文案必须说明所属临时侧边将关闭，执行中的主会话或侧边需先停止。

持久侧边删除还须通过原生关联列表递归核对未归档与已归档后代，包括重启后尚未加载的侧边；先对全部后代预检，取得全部后代写锁后再次核对执行、压缩、交互及未知回执。全部安全后按子级优先逐个原生删除，再删除主会话；不能用 `unsubscribe` 代替持久历史删除。任一后代删除失败或结果未知时停止，不派发主会话删除，保留该后代原删除保护；已确认的子级删除不回滚或重放。

删除时原生关联分页必须明确返回数组及有效结束游标，逐页核对父关联、去重并防止游标循环；分页缺字段、非法游标或身份变化均不视为空列表。删除前按原生会话 ID、原父关联和明确安全状态再次核对，缺失或未知状态直接拒绝。祖先与后代的删除请求在取得任何会话写锁前串行化，防止双方各持一端锁后互相等待。其他原生客户端创建的侧边同样在删除意图中保存父关联，结果未知后即使退出列表，也不能解除父会话的删除保护。

### Open in 的应用识别与前台显示

Elves Windows 本机客户端的 Open in 由本机 Harness 独立检测和启动应用。远程 PC、手机网页、PWA 和 Android 不显示顶部 Open in、会话列表打开方式及正文 Explorer / 打开方式入口；服务端在读取应用列表和启动应用前核对真实本机监听及本机授权，通用 `openWorkspace` action 同样拒绝远程设备，旧缓存或直接请求不能绕过。文件预览、浏览器打开及复制路径保持原行为。

支持 VS Code、Visual Studio、IntelliJ IDEA、Sublime Text、GitHub Desktop、File Explorer、Git Bash、Cmder、Rider、PowerShell 和 WSL；只显示当前服务实际检测到的目标，前后端应用 ID 列表同步维护。

IDEA 检查 App Paths、PATH 和常见 JetBrains 安装目录。PowerShell 优先使用 PowerShell 7，缺少时使用系统 Windows PowerShell。PowerShell 和 WSL 在已安装 Windows Terminal 时使用独立窗口，并明确指定所选程序和会话目录；缺少 Windows Terminal 时正常显示启动所选程序。

Git Bash 和 WSL 的主按钮及展开菜单图标从当前服务实际检测到的可执行文件提取，以 PNG 数据返回，不向网页公开安装路径。图片缺失、格式无效或加载失败时沿用原终端图标；其他应用图标和启动方式保持不变。

WSL 项仅对当前实际由 WSL 实例执行、且已取得原生对话恢复信息的会话显示。判断依据是服务端保存的实例身份，目录是 Windows 盘符、`/mnt/` 挂载还是 WSL UNC 不改变实例归属；本机实例不因项目位于 WSL 目录而获得入口。点击后使用同一发行版、用户、Linux 工作目录及 CLI，进入当前已有对话：原生任务仍存在时使用 `attach`，空闲历史使用原生会话 ID `resume`；不另建对话或重复执行当前任务。启动继承该 WSL 用户的登录环境和时区，不借用其他实例。当前 Codex WSL 执行适配器尚未就绪，本机 Codex 会话不展示 WSL 项。

用户点击打开后，应正常显示应用，并恢复、激活所选应用的新窗口或当前目录对应的已有窗口。PowerShell 和 WSL 使用 Windows Terminal 新窗口时只确认本次新窗口，不能用同目录的旧终端代替当前对话；PowerShell 标题显示初始目录，WSL 标题显示对话名及原生会话短 ID，用于区分同目录下的不同对话。只通过 Windows 系统接口处理目标应用，保留独立服务边界，不复用 Codex App 或管理器执行通道。

启动成功与前台显示分别确认：仅在目标窗口实际成为前台时回执 `foreground: true`。窗口尚未出现或 Windows 未允许激活时保留启动成功回执，明确提示用户在任务栏查看，不因激活失败重复启动。不得模拟按键或修改系统前台限制来伪造成功。

### Elves Windows 客户端窗口恢复

Elves Windows 客户端主窗口在启动时恢复关闭前保存的逻辑大小和物理位置，关闭到托盘及退出时继续保存。目标显示器的 DPI 用于换算实际像素尺寸；同屏且原窗口完整可见时，大小和位置逐像素保持不变。

当前显示器无法完整容纳时，只缩小到显示边界并平移必要距离；原位置已离开所有显示器或配置无效时回到屏幕中央。最大化状态和用于还原的普通窗口尺寸分别保留，不能把最大化后的屏幕尺寸覆盖为普通窗口大小。

### Windows 独立客户端编辑区

Elves Windows 客户端切到后台前若焦点位于会话编辑框，切回前台后恢复该编辑框的焦点和光标选区，可直接继续输入；后台前焦点位于侧边栏、按钮或其他控件时不抢到编辑框。窗口尚未取得前台焦点或编辑框已禁用时不强行恢复。

主窗口和独立会话窗口均须处理 Alt+Tab、切换其他程序复制、系统快捷键及最小化后返回：原生父窗口取得前台且键盘焦点停在父窗口时，将焦点交还其会话 WebView；已经聚焦的原生菜单按钮、网页控件或其他程序不受影响。网页在编辑框 `focusout` 时提前记录选区，不依赖随后到达的窗口 `blur`；只有焦点实际恢复成功后才消费记录。记录按当前编辑框节点、会话、选择版本和设备授权隔离，切换会话、主动点击其他位置、打开对话框或输入禁用后不能用旧选区抢焦点。返回后直接输入或 Ctrl+V 应落在原选区，继续使用既有剪贴板处理，不读取或改写剪贴板。

编辑框内容超过最大高度后，仅在实际输入、回车换行、粘贴或输入法编辑时，无选区且光标位于文本末尾才跟随到底部，保持光标可见。主输入框和历史消息编辑框均须保留手动滚动到顶部或中间的阅读位置；即使光标仍在末尾，会话状态刷新、消息更新、外观及尺寸重算也不能拉回底部。修改中间内容、撤销重做或载入草稿时不强制跟随；重算高度后恢复原滚动位置，内容缩短时由实际可滚动范围限制。

“+”使用正常前景色 `var(--text)`，不再以次要文字色显示。提示词优化工具栏入口在普通、加载和完成状态始终使用同一个原有彩色 `✨`，显式使用彩色 Emoji 字体及 Emoji 呈现；完成后保留淡绿色背景与“恢复原提示词”提示，再次点击仍恢复原文，不切换单色矢量图标，`/` 菜单继续使用原有矢量图标。“+”在悬停、按下、键盘聚焦和菜单展开时使用 `var(--composer-hover,var(--hover))` 背景，与模型按钮的交互一致。

### Claude 会话退出回收与启动补偿

空闲进程回收以退出为主、启动补偿为辅。Elves 托盘退出及安装升级时，先停止新派发和自动重连，再通过同一实例的原生 CLI 停止安全空闲会话，确认完成后结束 Windows 后台。普通网页断开和 Elves 主窗口收进托盘不触发回收。关闭远程会话只停止网页及公网入口，Elves 本机使用的 Harness、原生连接和代理继续运行。

只处理本服务创建且保存了原生会话及后台任务身份的 Claude 会话。执行、审批、问答、压缩、未发送草稿、后台任务、原生队列或发送／编辑结果待确认时保留会话；无法确认身份或读取状态时也不停止。轮次 `done` 不能代替进程退出证据。

每项回收分别保存已停止、保留原因或结果未知。正常退出后，启动只核对未确认项；缺少旧版记录或上次异常退出时，才补登记尚未完成回收的受管身份。已确认停止的历史会话后来被原生终端恢复，不因服务启动再次回收。后台仍运行时每 15 秒复查待回收项。用户通过远程继续使用某个会话时取消旧请求，停止与发送共用会话锁，迟到回执不得影响新任务。意图保存失败时不停止目标；异常强制结束不报告为回收成功。

整体清理最多等待 55 秒，本机退出接口保留 60 秒处理预算，调用方保留 65 秒响应预算；超时项继续等待启动补偿。安装包使用包内新版退出 helper，旧服务没有接口时保留受管身份供新服务启动核对，不复用任何 Codex App 桥接。

Claude 新建及恢复后台会话都必须使用当前 WSL 用户的有效登录时区。旧任务保存的时区缺失或不一致时，在继续发送前核对安全空闲状态；执行、交互、草稿、后台任务或状态不明时保留会话。原生 `respawn` 不接受新的时区设置，直接带新设置 `--bg --resume` 会创建副本，因此仅对已核对无 worktree、身份与启动参数可安全保留的任务，通过原生 CLI 停止任务、移除后台登记，再用同一原生 UUID 和正确的 `env.TZ` 恢复，保留原生历史及模型、思考深度、权限和自动压缩参数。移除前在目标 WSL 用户的持久私有目录原子保存不含认证配置的恢复记录，原任务的运行文件先保存，并在新进程启动前恢复原路径；同名冲突时保留文件并明确失败。失败重试沿用同一 UUID；身份和保存的时区核对成功后删除记录。自定义启动设置或 worktree 无法安全迁移时明确说明原因，不停止任务、不发送消息。不强制重启统一 daemon，不修改系统时区或用户全局 Claude 设置。
