# 手机网页、PWA 与 Android

[返回项目首页](../../../README.md) · [产品规范索引](../README.md) · [远程会话接入指南](../sessions/remote-access-guide.md) · [Android 构建与运行](../../android.md)

手机通过网页、PWA 或 Android App 访问电脑上的 Harness，使用同一组项目、实例和会话。任务仍由电脑上的原生 Codex / Claude 实例执行；手机不需要安装这些 CLI。

## 准备电脑端

1. 打开 **Elves**。客户端自动启动本机 Harness 并进入工作区，不需要先填写远程地址或在连接页启动服务。
2. 在底部“设置”中检测并配置需要使用的会话实例，确认电脑端能够正常打开项目和会话。
3. 进入左侧主导航的 **远程会话**，启用网页服务。默认远程网页端口为 `45222`；本机工作区的 `45223` 不用于手机接入。
4. 在“访问密钥与设备授权”中生成或填写访问密钥并保存。
5. 配置手机能够访问的地址，检查网页服务与入口状态，再将地址复制到手机。

电脑需要保持开机且不休眠。关闭 Elves 主窗口收进托盘后仍可继续访问；从托盘退出 Elves 会回收其拥有的后台。启用远程会话不改变本机授权，也不控制本地代理开关。

## 选择访问地址

| 场景 | 地址与设置 |
| --- | --- |
| 同一局域网 | 使用电脑的局域网地址与远程网页端口，并配置可供局域网访问的监听地址及防火墙规则 |
| 不同网络 | 在“公网入口”配置并验证 zrok 或 FRP 主入口，使用页面给出的固定公网地址 |
| 第二线路 | 根据需要配置 ngrok；它独立于 zrok / FRP 主入口，不自动取代主入口 |

`127.0.0.1` 只表示当前设备，不能把电脑的回环地址直接作为手机地址。公网使用 HTTP 时，页面会提示传输不加密；HTTP 隧道内部使用 TLS 不代表公网网页已使用 HTTPS。

公网配置中的“正在编辑”和“当前生效”分别表示候选表单与正在使用的入口。先保存、测试，再按页面提示应用；切换公网 Origin 后需要在新地址重新登录。详细步骤见[公网入口配置](../../remote-public-access.md)。

## 连接手机

### 浏览器与 PWA

1. 在手机浏览器中打开电脑端提供的地址。
2. 输入已保存的访问密钥，完成设备授权。
3. 选择实例和项目，打开已有会话或新建会话。

浏览器提供安装或添加到主屏幕入口时，可以使用 PWA。该入口是否可用取决于浏览器和安全上下文。网页与 PWA 使用同一服务地址和设备授权规则。

### Android App

安装 Android 独立版本的 APK，在 App 中填写同一 Harness 的服务地址和访问密钥。App 使用自己的授权缓存、资源更新和系统权限；不与 Windows 版本号绑定。

APK、应用更新与诊断说明分别见 [Android 使用与构建](../../android.md)、[应用更新](../../android-update.md)和[诊断日志](../../android-diagnostics.md)。APK 更新与网页资源更新是两套独立流程。

## 会话与设置

- **项目与实例：** 通过侧栏查找会话、筛选实例或选择项目。会话始终使用它所属实例的原生执行环境，不自动改投其他实例。
- **消息与执行：** 可以继续对话、查看执行过程、处理已适配的审批和问答；队列、停止及编辑能力以当前会话和原生引擎提供的能力为准。
- **模型与思考深度：** 在输入区选择该实例实际提供的模型和思考深度，后续提交按已确认的配置执行。
- **文件与关联会话：** 手机使用整页方式查看文件、变更及关联会话。详细边界见[会话工具说明](../sessions/workspace-tools-and-side-sessions.md#菜单入口与页面层级)。
- **共享设置：** 外观由当前客户端独立保存，其他设置的共享范围及本端状态见[设置规范](../core/product-behavior.md#远程设置分类与实例配置)。
- **设置与退出：** 在会话列表底部点左侧“设置”直接打开设置，或点右侧“退出”撤销当前设备授权；两者是[独立按钮](../core/product-behavior.md#统一左侧主导航)。

远程只读和审批策略由电脑端配置。功能不可用或原生接口缺少能力时，页面会显示限制，不通过 Codex App 代执行。远程会话关闭、换密钥或撤销手机设备，不影响 Elves 本机使用。

## 连接与恢复

| 现象 | 检查与处理 |
| --- | --- |
| 无法打开地址 | 核对电脑是否运行、网页监听是否启用、手机地址是否可达，以及防火墙或公网入口状态 |
| 访问密钥无效、授权失效 | 核对当前服务地址与已保存的密钥，必要时在该地址重新授权；不要把旧地址的 Cookie 复制到新地址 |
| 已连接但只能查看 | 检查该服务的远程只读及审批策略，并确认实例本身提供相应能力 |
| 发送结果未知 | 先查看原会话和原请求回执，不自动重发，也不要用新请求 ID 重复提交同一操作 |
| 更新后仍显示旧界面 | 关闭并重新打开该地址的页面或 App，让完整资源快照在下次导航启用；不要先清除草稿或授权数据 |
| 页面断线 | 保留当前输入，等待连接恢复；恢复后的正文与状态以同一会话的原生确认结果为准 |

缓存与恢复机制见[会话展示缓存](../sessions/display-cache-and-recovery.md)和[网页资源交付](../../pwa-android-implementation.md)。
