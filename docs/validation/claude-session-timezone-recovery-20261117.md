# Claude 旧会话时区恢复验收

日期：2026-11-17。

## 问题与修复

旧后台任务保存的启动设置没有 `env.TZ`。即使连接端已经通过 WSL 登录环境取得 `America/Los_Angeles`，原生 `respawn` 仍复用旧任务参数，执行进程可能继续使用系统时区。

Claude Code 2.1.326 的实际行为：

- `respawn <id> --settings ...` 返回成功，但明确提示附加参数被忽略；把 `--settings` 放在子命令前也不会更新已保存参数。
- 已停止的旧任务直接带新设置执行 `--bg --resume <uuid>` 会创建副本。
- 使用原生 CLI 移除已停止、无 worktree 的后台登记后，可以携带新设置恢复同一个 UUID；预先恢复原任务的运行文件不妨碍 CLI 使用原身份。

本次在继续发送及恢复任务时检查保存的时区。仅在确认安全空闲、没有草稿、交互、原生队列或后台任务时迁移；保留原启动参数、名称、工作目录、原生历史和运行文件。认证环境、外部设置文件、worktree 及无法安全保留的会话专用设置不进入自动迁移。

恢复记录以 `0600` 权限原子保存在目标 WSL 用户的持久私有目录。移除后台登记之前保存必要参数及运行文件，失败可以按同一 UUID 重试；恢复成功后清理记录。历史编辑和环境恢复使用同一会话锁，不强制重启共享 daemon，不修改用户全局设置或系统时区。
