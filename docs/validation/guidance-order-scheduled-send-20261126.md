## 引导消息渲染到整轮末尾

- 原因：Claude Code 2.1.332 把执行中吸收的引导记为 `queued_command` 附件，`prompt` 改为内容块数组、
  以 `hostsOwnTurn` 标记，不再带 `humanTurn`/`origin`；读取器只认旧形态，整行丢弃。原生行 UUID 与发送帧
  UUID 不同（只在 `source_uuid` 里保留），待确认记录也对不上，网页只能把本地回执排在整轮末尾。
- 改动：读取器同时识别两种形态，按 `source_uuid` 对账；任务通知等非人工附件仍隐藏。
- 验证：读取器单测 99 项通过；Rust 投影用例确认引导停在工具结果与后续回复之间；用本机真实会话只读回放，
  8067 条消息读取 0.6 秒，引导位置正确、待确认记录清零。

## 定时发送

排查并修复：

0. **首次设置定时完全无效**：时间弹窗点“确定”时先记录草稿、后画编辑框标记，草稿快照以编辑框实际标记为准，
   所选时间立即被清空（只有修改已有标记的时间能成功）。已调整顺序；用 Chromium 加载真实模块分别按原顺序和
   修复后各走一遍确认。
1. 编辑框标记只显示时间且样式与“目标”不一致；改为已确认的“时钟图标 + 定时发送 · 今天 HH:mm”。
2. 发送超过 40 秒（单次等待上限）会被记为失败；改为按原回执继续等待，不会重复发送。
3. 发送中的消息仍可取消，取消后消息照样发出；现在服务端拒绝取消并显示“发送中”。
4. 结果未知与确定失败都显示“发送失败”，容易诱导重发；分为“发送失败”和“结果待确认”。
5. 失败行与错误文字共用样式类名，整行错排；多条定时消息时各行叠压并盖住目标栏。改为独立状态属性、
   定时列表限高内部滚动。
6. 同一会话上一批还在发送时下一轮可能并发认领，顺序会颠倒；写盘失败时消息会一直卡在“发送中”。
7. 读取进行中收到的变更丢失、切走又切回时列表为空、断线恢复后不补读。
8. 内置网页比服务端新时每次切换会话都提示读取失败；改为服务端声明能力后才显示和读取。
9. 取消被服务端拒绝时没有任何提示。
10. 创建定时消息会读取整份会话详情（Claude 还要经 WSL 检查占用进程）；改为只核对会话存在。
11. 临时侧边会话关闭后其定时消息残留。
12. 此功能接入后前端状态测试多出约 40 项失败（未声明新全局），已补默认测试装配。
13. 只有时间标记、没有正文时“停止”按钮被顶掉；旧版 Claude 会话执行中或压缩中无法设置定时消息。

保留已知行为：到期时 Elves 未运行，下次启动后立即补发（没有过期上限）；失败或结果待确认的消息只能取消，
没有“取回到输入框”。

界面用 Chromium 核对过浅色、深色、390px 宽度、超量列表滚动和时间弹窗焦点。另用项目的网页开发入口接本机
模拟后端走完整应用：“+”菜单 → 定时发送 → 确定 → 输入 → 发送（只发出 `createScheduledMessage`，字段正确、草稿清空、
列表出现该条）→ 取消；点击标记可改时间，退格删除标记即取消定时。

## 日志异常

- 单元测试进程写入真实诊断日志（含伪造的故障事件）：测试可执行文件未指定状态目录时不再写默认日志。
- Codex Skill 目录读取失败每 60 秒重试一次（单个会话累计 138 次）：改为指数退避，最长 30 分钟。
- 执行失败事件此前只记结果不记原因；`remote_access.execution` 现带截断的失败原因，连接请求被拒绝时带
  服务端拒绝说明（固定文案，不含地址和凭证）。
- 403（累计约 220 条，集中在 `/api/session`、`/api/channels`、`/api/events/ws`）：来源尚未确认，需装新版后
  按拒绝说明定位。
- 未处理：本地代理到上游 Responses WebSocket 连接重置（上游中转行为）、Codex CLI 自身的 stderr 警告。

## 冷启动

当前发行版、隔离配置、只发 `initialize` 控制请求时测得：

| 场景 | 耗时 |
| --- | --- |
| 新会话（无 MCP、无钩子） | 0.26–0.28 秒 |
| 恢复 5 / 20 / 40 / 77 MB 转录 | 0.33–0.52 秒 |
| 8 个 MCP 服务 + SessionStart 钩子 | 0.40–0.49 秒（约 1.5 秒内全部连上） |

CLI 初始化本身不能解释日志里发送 12–29 秒的记录；模型首个输出约 25 秒属于上游耗时。改动：

- 发送前同步在原生记录无变化时不再重发整份历史快照（21.6 MiB 会话读取器侧约 0.17–0.18 秒，另加上层解析和投影）。
- Claude 权限模式清单过期时先用旧清单、后台刷新，不再让发送等 `claude --help`（约 0.3 秒）。
- 新增 `claude.sdk.cli_started`（各启动阶段耗时）和 `claude.control.slow`（超过 1 秒的控制请求）诊断事件，
  需装新版后用真实数据确认剩余耗时所在。
