# AGY 对照 Claude 的检查与修复验收

## RCA 结论

- 状态：下表列出的源码缺陷已确认并修复；全部 AGY 能力的运行验收仍为部分确认，边界见“未闭环项”。
- 检查基线：`d32b3db765e499c0cd24f98ed9d3e064bb184bd2`，Windows 本机官方 `agy.exe 1.5.18`。检查时正式服务资源为 `2026112612`，本次源码资源递增至 `2026112707`。
- 现象：部分操作在原生拒绝后仍返回成功，失败时队列消息消失，权限切换或结束轮次可能卡住，选项回答被映射为取消。
- 直接原因与根因：接入层吞掉 RPC 错误、提前移除队列或确认正文、跨异步操作重复持有同一互斥锁，以及问答载荷与共享前端不一致。
- 系统性原因：原有接入回归主要检查成功投影、静态字段与基本队列操作，没有覆盖原生拒绝、连接中断、准备失败和锁重入。此次在原有测试模块补入失败路径与状态保持断言。
- 关键因果链：用户操作 → 本地提前更新状态/未核对原生结果 → 原生拒绝或准备失败 → 本地仍确认成功、丢失消息或无法完成操作。

## 证据

| 检查项 | 已验证的原因 | 修复及验证 |
| --- | --- | --- |
| 模型、思考深度与权限 | 设置失败被忽略；本地保存值被当成原生实际值；无限制切换在持有运行时表锁期间再次取锁 | 原生拒绝传回用户；重连重新应用设置；不继承不支持思考深度的模型等级；释放表锁后切换连接 |
| 普通发送与引导 | 发起异步 `session/prompt` 即确认成功；原生没有独立即时接收回执 | 普通发送等待当前原生执行证据或成功结果；引导等待对应 RPC 成功；正文只加入已确认消息 |
| 队列与目标 | 准备前取出消息；启动失败遗漏恢复；不支持引导时直接取消原任务；旧 `queueOnly` 使空闲会话入队 | 消息持久保留至确认；失败暂停；未知不重发；保留运行中任务；准备失败暂停目标；非法排序不改变原顺序 |
| 并发与结束状态 | 多个 prompt 复用原轮次，首个结果可提前清除执行状态；清理审批时重复取同一锁 | 全部在途 prompt 结束后再完成轮次；等待引导时可审批、停止及释放服务；清理审批先释放请求表锁 |
| 问答 | 前端提交 `response.answers`，AGY 却读取顶层 `answers`；自由输入不能映射为原生 optionId | 对齐载荷；只显示原生选项与选中态；无效答案及写入失败保留请求；Claude 原有自由输入保留 |
| 历史与显示 | 未宣告 append 能力时静默丢弃前文；新运行时准备失败可能已替换旧连接；空计划与零缓存被当作缺失 | 追加能力不足时拒绝编辑；全部准备成功再替换；待发/未知消息、队列编辑或审批存在时禁止历史编辑；空计划清除旧值，明确零缓存显示零 |

证据性质：上述原因来自实际代码路径、隔离协议反例及修复后的对应断言。仅新增失败断言、尚未修改生产实现时，最初 12 项反例全部失败。

### Token 更新专项

- 前端原已共用 `syncComposerMetrics()` 的执行中 2 秒、空闲 15 秒读取，以及底栏数字滚动和详情卡。差异在 AGY 后台：运行中跳过转录同步；把上下文 `used` 当累计量；按数组长度或最后一轮回填用量；用轮询时间推进速度分母；缺失缓存被填零。最初针对这些分支的 5 项反例均失败。
- 官方 ACP 独立会话只读取本次准备的 `sample.txt`。一轮尚未结束时，第一次模型调用已落盘输入 `17675`、缓存 `0`、输出 `230`；第二次调用已落盘输入 `2386`、缓存 `15618`、输出 `47`。最终 PromptResponse 为未缓存输入 `20061`、缓存读取 `15618`、输出 `277`、总量 `35956`，与两次调用之和一致；上下文最后占用为 `18051`，不能充当累计量。
- 原生 `PLANNER_RESPONSE.created_at` 与请求发起时间一致且精度为秒，记录没有实际完成时间。因此用量可从完整调用记录补齐，首 Token、耗时和速度必须使用真实通知或结束记录，不能由该时间戳推算。
- 新统计路径仅在后台线程读取所属实例、当前原生会话的完整 JSONL 行：首次最多尾读 8 MiB，之后增量读取；按原生 `step_index` 去重，最多缓存 64 个文件、128 个近期输入身份和 2048 项调用明细。旧调用折叠为累计；不完整历史隐藏无法确认的总量，不完整计费明细保留费用未知。不在统计热路径加载或覆盖正文，不启动额外 CLI。
- 轮次按用户输入指纹和时间匹配，同秒相同输入无法唯一归属时保持未知；读取期间原生会话或历史身份改变时丢弃旧结果。执行中的速度以实际用量观测为准，重复读取不改变分母。新增前端断言也复现了缓存恢复后动画状态丢失，修复为重建数字节点时同时清除旧渲染标记。
- 最后复核扩展原有断言，另复现 3 项边界问题并补修：最终 ACP 回执先到、JSONL 尚未落盘时保留已确认累计；旧步骤在下一条输入之后重复出现时保留原归属；缓存倒计时与速度使用同一次真实用量观测，不使用请求开始时间。
- Chrome 当前源码 Token 组件：Codex、Claude、AGY × 深浅主题 × 320px/1280px 共 12 组通过，覆盖实时数字动画、固定卡片更新、恢复缓存后的动画、换轮关闭及视口边距；另验证鼠标悬停和未知统计隐藏。首次脚本中的浮层消失来自切换视口后的异步 resize，稳定视口后全部通过，无需修改浮层逻辑。此处为独立源码组件验收，未切换正式服务。

## 已排除解释

- 部分界面效果来自运行安装版落后于源码，不能归因于当前源码缺陷。
- AGY 内置 `/compact` 入口已有禁用判断；没有恢复协议不支持的压缩、原生分支或文件回退。
- 自动额度轮询和 AGY 自动命名实例禁用属于现行限制，本次未撤销，也未用 `agy -p` 反复探测。
- 草稿已有实例隔离；启动恢复也已有执行状态与队列恢复处理，没有新增开发期旧状态迁移。

## 异常状态溯源

- 适用约束：原生设置明确拒绝时，不能保存为已生效；消息尚未确认接收时，不能移除唯一待发副本或展示发送成功；已有待发/未知操作时不能改换其原生历史。
- 依据：主产品规范中的发送回执、历史编辑约束，以及 AGY 公开 ACP 返回值；本次场景由拒绝/断线/准备失败的隔离响应命中。
- 首次违反点：设置的 `.is_ok()`/忽略错误分支、发送前 `take_by_id`/`pop_next_ready`、后台 prompt 结果被丢弃、历史编辑准备完成前替换运行时。
- 修复后的边界：前置失败保留原状态；成功回执或当前原生执行证据后确认；结果未知保留原消息与原回执，不补造成功，不自动重发。
