# 工作区大文件预览：Elves 建议与 Codex App 对照

记录日期：2026-11-28。本文保留**实施前**的文本与日志建议和官方包对照。用户随后确认按顺序实施且不提供原文件下载；实施、验证和未覆盖项见[本机与远程文件查看规划](../workspace-file-preview-plan.md#实施与验证记录)。现行规则见[内容查看](../product-standards/sessions/workspace-tools-and-side-sessions.md#内容查看)。

## 保留的 Elves 方案

- 适用于 Elves Windows 本机客户端（含独立文件窗口）和远程网页、PWA、Android 的工作区文件预览，不是模型读文件或上传附件的限制。
- 保留 4 MiB 作为文本**是否一次读完**的分界线，不作为能否打开的分界线。4 MiB 以内维持原有预览；超过后以只读纯文本打开，按需分块，建议首版每次最多读 256 KiB，不在前端拼回完整文件。源码、JSON、Markdown 默认看开头，可向前、向后翻或直接跳至首尾。超过阈值的 Markdown 不渲染不完整的富文本。
- 可识别为文本的大 `.log` 默认从末尾打开，能向前翻查原因，也能跳回开头。例如看 200 MiB 的日志，不应为首屏先读前面近 200 MiB。读取时保留 UTF-8、带 BOM 的 UTF-16 编码及字符边界；即使整份 JSON 只有一行，也不能为了读完整行而加载整个文件。
- 前端只渲染可见内容及少量前后行；界面标明当前片段和文件总大小，不把局部复制或搜索说成全文结果。本机与远程使用独立 Harness 自己的授权读取，不依赖或桥接 Codex App。首版不加“最大文件大小”设置。
- 这部分只确认文本查看；图片、PDF、Office 和 Git 差异不随文本分块方案放开。非文本格式的后续提案不改变本次已确认的文本行为。

## 官方 Codex App 怎么做

核对的是本机 Windows 安装包 `OpenAI.Codex 26.1120.6357.0`（包内应用版本 `26.1120.50957`）的工作区文件标签。下表来自安装包静态代码，不是 OpenAI 对所有版本、所有文件或云端的承诺，也不是大文件性能实测。聊天附件、制品查看器和 Git 差异的限制没有当作普通文件限制。

| 场景 | 安装包里确认的行为 | 对 Elves 的启发 |
| --- | --- | --- |
| 本机只读源码预览先识别文件 | 先用 `stat` 取文件类型和大小；普通文件在采样允许的大小内，查看器请求最多 **4 KiB** 的文件头，辅助判断文本、二进制或媒体类型。已知大小**大于 256 MiB** 的普通源码文件不进入正文组件，提示同时显示文件大小和预览上限。 | 先拿元数据，再用有限字节识别内容。Elves 可以对大文本直接选分块模式，不需要读取正文才知道要降级；明确区分不能识别、没有权限与只显示了部分内容。 |
| 读取和显示源码 | 本机只读源码组件通过 `workspaceFiles.readText` 取得完整 `contents`；显示端另算滚动视口，只为可见行及前后缓冲区绘制内容。**少画行不等于少读文件。** | 采用可见行渲染，尤其是几 MiB 却有几十万短行的文件；在此基础上，Harness 再从磁盘按字节范围读取，否则远程首屏仍要等整份文本。 |
| 可编辑文本走另一条路径 | 以进入 Pierre 文本编辑器的 `.txt` 为例，**大于 10 MiB** 时以只读模式打开；**大于 20 MiB** 时该编辑组件拒绝加载。它和上一行的只读源码预览不是同一条路径；不能据此认为超 20 MiB 一定自动切入 256 MiB 的查看器。 | 借鉴按操作设限，不照搬数值。Elves 文件面板本来就只读，不为大文件引入编辑器，也不扩大图片、Office、PDF 或 diff 的上限。 |
| 跳行与阅读位置 | 源码查看器可预览目标行；解析器支持 `-1` 表示最后一行，取消跳转可恢复先前的选中行和滚动位置。此路径基于已加载的完整文本计算行数。 | 首版保留“跳到末尾”和返回原位置。日志可直接从文件尾向前读；若后续增加 `-N`，不要为了定位倒数几行而先读完整日志。 |

另有一个不宜照搬的做法：包内一条托管执行环境路径在请求类型样本时先调用 `fs/readFile`，拿到全量数据后才截取样本；不能把本机按需采样的行为推广到所有远程路径。Elves 应在文件所在的 Harness 进程内完成有限读取，远程设备只接收请求的片段。此次没有证据表明上述普通源码预览提供任意大文件按字节翻页或大 `.log` 默认读末尾；这两点保留为 **Elves 自己的设计**。

## 落地时先验证什么

1. 同一份 200 MiB 日志在本机与远程首次打开均显示末尾，正文单次最多读取和传输 256 KiB；点“开头”能回首段，普通源码仍从首段开始。
2. 用 200 MiB 单行 JSON 和含大量短行的文本分别验证：首屏不为换行读完整文件，前后翻不丢字、不重复，滚动时页面元素数量不随已读总行数一直增长。
3. 每次取片段仍校验来源会话或项目、授权和文件身份。日志被替换或截短时，不把旧片段和新文件拼接；提示变化后可重新读取。关闭标签或切换授权后，迟到响应不能写回。
