# 后台命令无窗口调用审查与验收

日期：2026-11-27。

## 范围

落实 [AGENTS.md 的后台命令规则](../../AGENTS.md#后台命令默认无窗口启动强制)。审查 Elves 客户端、独立管理器、Harness、共享核心库及项目脚本中的进程创建入口；区分操作系统进程、Rust 异步任务、仅运行于 WSL 的 Python 子进程和用户主动打开的外部应用。

## 修复与保留

| 入口 | 审查结果与处理 |
| --- | --- |
| AGY `models`、`-p "/usage"` | 原共享命令构造器缺少隐藏标志；本机与 WSL 两条分支改用统一隐藏命令构造器 |
| AGY WSL 时区探测 | 原 `wsl.exe` 直接启动未隐藏；接入同一构造器，保留目标发行版、用户、Home 和登录 shell |
| 上游工作树的分支校验、Git 可用性及 Git 操作 | 三个入口缺少隐藏标志；统一构造器覆盖其调用链 |
| 上游工作树的 SSH 调用 | 缺少隐藏标志；补齐，保留 `BatchMode`、连接超时、参数及错误回传 |
| 网页资源检查的 Node 子进程、发布说明脚本的 Git 子进程 | 补充 `windowsHide: true` |
| ACP 主连接、Claude WSL、命名、实例/权限探测、隧道与服务启动 | 已在各自公共构造或输出入口设置隐藏标志，保持现有行为 |
| CLI Wrapper 后续子进程 | 沿用父进程的无窗口控制台状态；既有多级子进程回归通过，不改动用户从终端启动时的交互能力 |
| Open in、打开浏览器、打开资源管理器 | 用户主动触发的可见交互入口，保留可见窗口 |
| WSL 内的 Python CLI/宿主子进程 | Linux 进程不创建 Windows 控制台；Windows 侧 WSL 启动入口已有隐藏配置 |
| PowerShell `Start-Process` | 两个项目入口均已有 `-WindowStyle Hidden`，无须修改 |

新增 `elves_core::process::hidden_command`，在 Windows 进程创建前复用 `windows_create_hidden_process()`；AGY 使用 Tokio 的标准命令转换保留该配置。其他平台不增加 Windows 专属行为。修复不改调用参数、权限、协议、工作目录或错误处理，也不增加任何官方查询频率。

## 验证

- 公共隐藏命令及后续子进程原生回归：1 项通过。子进程检查 `GetConsoleWindow() == 0`，标准输入输出、错误输出和非零退出码均保留。
- AGY 额度模块定向回归：4 项通过，包含真实本机子进程无控制台验证，以及本机可执行文件和 WSL 登录参数检查。
- 上游工作树只读回归：6 项通过，覆盖正常/非法分支名、Git 可用性与引用解析。
- Windows GUI 宿主验收：4 组通过。临时宿主直接链接本次 `elves-core`，核对 PE 子系统为 GUI，并在没有控制台的父进程中分别执行同步/Tokio 异步、直接 EXE/CMD 包装两种组合。父进程与实际命令进程的控制台句柄均为 `0`；输入 `gui-payload`、标准输出、错误输出及退出码 `17` 均完整传递。
- `node scripts/check-harness-assets.mjs` 通过：153 个资源、146 个 JS 模块检查成功。
- 发布说明脚本使用仅含一次提交的本地 Git 范围完成读取冒烟；没有创建标签或发布。
- `git diff --check` 通过。

测试使用隔离的测试子进程，没有向真实 AGY/Claude 会话发送内容，没有执行官方额度查询，也没有启动真实 WSL 发行版。WSL 的验证范围为 Windows 启动配置与登录参数，不能视为目标发行版的实际运行验收。
