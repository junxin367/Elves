# AGY 原生额度提示验收

## 范围与行为

产品约定见[Antigravity ACP 实例](../product-standards/core/product-behavior.md#antigravity-acp-实例)中的“额度与原生失败提示”。

- ACP 最终错误保留原生来源、错误码、原文与明确文本详情，轮次保存后继续提供给历史接口。明确 RPC 拒绝与断线分开处理。
- 页面沿用普通回复样式，仅展示原文、复制和本轮结束时间；主错误与扩展文本分别原样展示及复制，不拼接、翻译或裁剪空白，不解析提示中的 HTML，不转换原文内的时间或时区。原生正文已经包含相同提示时也按纯文本渲染并去重。
- 不新增手动重试、定时续发或额度恢复查询。CLI 自身重试仍由 CLI 处理；最终失败沿用暂停队列和持续目标的规则。
- 导入的会话在 Elves 接续执行后，本地转录刷新仅同步用量，不覆盖已保存轮次及最终错误。仅读取本地中间错误日志不能证明本轮已失败，不据此生成额度提示。
- 未修改 Claude、Codex 的额度提示，也未改动账号额度查询接口。

## 补充：历史导入与压缩错误

- 只读核对已有原生转录，确认 `ERROR_MESSAGE` 使用 `error` 字符串、状态为 `DONE`，之后仍有正常 `PLANNER_RESPONSE`。因此单条错误记录不足以认定整轮失败。
- 历史错误从 `error` / `content` 的明确文本字段读取，作为原文活动记录保留；按原生步骤去重并保持先后顺序，不再设置整轮 `turn.error`。前后空白、CRLF 与扩展说明保持原样，时间只用记录自身的合法原生时间，缺失时省略。
- 手动压缩最终错误复用 `acp::turn_error`，压缩模型准备阶段也不再给原生错误添加前后缀。失败原文与扩展详情落盘后可从历史接口恢复。
