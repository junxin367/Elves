# Codex 在新聊天中分支验收

## 实现范围

- Codex 持久主会话的已结束回复下方增加 `⋯`，从“在新聊天中分支”复制该回复所属完整轮次及此前历史。
- `/` 菜单的“压缩”下方增加同名命令，支持 `/fork`、中文筛选及鼠标、Enter/Tab 选择，从最新进度创建持久分支。
- 工作目录只取服务端核对的源会话；无目的地弹窗，不创建 worktree，不回滚文件，不自动重发旧问题或草稿。
- 创建后打开新会话、聚焦输入框，保存编号标题与来源关系；用户已切换会话或授权时不抢回页面。
- 临时侧边、只读子智能体、只读设备与不支持的实例隐藏分支入口。侧边“+”及 `/` 菜单直接移除“目标”，普通发送、排队与压缩保持原规则。
- 沿用持久回执与幂等请求。超时、断网及刷新后只查询原请求；创建后的标题或本地来源保存失败提示附加错误，不重新创建。

## 原生 CLI 实测

本机 `codex-cli 0.164.0`，使用独立 `CODEX_HOME`、独立 Git 工作目录及回环模拟 Responses SSE 服务。未使用真实模型、账号凭据或已有会话，也未驱动 Codex App。

1. 创建持久主会话并完成 A、B、C 三轮。
2. 调用 `thread/fork`，参数为源 ID、源 `cwd`、`ephemeral:false`、`excludeTurns:true`、`threadSource:"user"`、`lastTurnId:B`。
3. 原生分页确认新分支仅保留 A、B；包含 B，排除 C。
4. 不提供 `lastTurnId` 再创建分支，确认保留 A、B、C。两个分支为不同持久线程，目录与源会话一致。
5. 两次分支操作没有产生模型请求；源会话仍为 A、B、C。
6. 向历史分支发送 D，实际模型请求上下文包含 A、B、D，排除 C；源会话仍不变。

全过程共 4 次回环模拟模型请求：源会话 3 次、分支中新输入 1 次。
