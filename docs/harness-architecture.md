# Elves 与 Harness 架构

Elves 是用户安装的桌面产品。Harness 是独立执行和管理产品，提供原生会话、实例设置、共享偏好、代理管理及可选远程接入。“远程会话”只表示网页、PWA、Android 访问 Harness 的能力，不表示整个项目或后台架构。

## 代码边界

| 目录 | 责任 |
| --- | --- |
| `apps/elves/` | 唯一 Windows 程序、原生窗口、启动和本机文件能力 |
| `crates/elves-assets/` | 客户端与 Harness 共用的内嵌网页资源，不包含执行或授权逻辑 |
| `crates/elves-harness/` | Harness 服务、Codex app-server、Claude CLI、管理命令及远程授权 |
| `crates/elves-core/` | 设置、模型能力、协议代理及原生供应商配置 |
| `crates/elves-data/` | 会话目录、SQLite、Markdown 和供应商数据同步 |
| `apps/elves-management/` | 工作区中的共享管理前端，不生成独立管理器 |
| `assets/harness/` | Elves 与 Harness 网页共用的工作区资源 |
| `apps/elves-android/` | Android 远程接入容器，保留正式签名和 applicationId |

依赖方向为客户端调用 Harness，Harness 使用 core 与 data，data 使用 core；客户端与 Harness 共用 assets。core 不依赖 Harness 或桌面窗口。管理接口使用固定白名单；所有执行仍经过目标原生实例，禁止桥接 Codex App。

## 启动与代理

默认运行 `elves.exe` 创建原生窗口，自动启动同一程序的 `--harness-service` 后台模式。后台先启动本机回环工作区，再发布私有管理端点，监视供应商代理开关及可选远程设置。客户端取得一次性本机证明，完成 HttpOnly Cookie 授权后打开工作区。

当前已启用供应商的本地代理开关为真时，后台自动启动协议代理；关闭时停止代理。代理默认端口 `45221`，与远程开关无关。供应商和显式协议配置按既有规则读取，不更改 Responses、Chat Completions 或 Anthropic 的路由语义。

## 本机与远程隔离

| 入口 | 默认监听 | 授权与策略 |
| --- | --- | --- |
| Elves 本机工作区 | `127.0.0.1:45223` | 独立本机 Cookie，一次性证明，不加入远程设备清单 |
| 远程网页、PWA、Android | 配置地址，默认 `45222` | 访问密钥、设备授权、只读和审批策略、公网入口 |
| 本地协议代理 | 默认 `45221` | 供应商的本地代理开关，局域网访问沿用显式开关与网段校验 |

远程监听不能占用本机工作区或代理端口。本机入口只接纳真实回环 Host，远程访问不能提交本机证明。远程关闭、只读、换密钥、撤销设备或公网故障不影响 Elves 授权、执行或代理。本机不发现或切换公网通道。

代理设置、会话管理、远程访问配置及全部管理接口只对已验证的本机身份开放。远程网页、PWA、Android 只提供会话和普通设置；管理资源与接口在服务端返回 403，不接受客户端类型标记作为授权。远程版本资源清单和 Android 内置包排除管理页面，缓存入口同步拒绝旧管理页面。

本机客户端不使用远程密码登录。Cookie 失效后，受限原生命令重新建立或恢复本机 Cookie，随后只恢复会话读取；草稿与待确认回执保留，不重发写操作。本机恢复命令不接受目标地址，也不向网页返回令牌。

## 数据与兼容

共享设置、历史和授权继续使用既有用户状态目录。已发布协议字段、Cookie、缓存键和 Android 标识按兼容需要保留旧名称；它们不作为新产品名。Windows 安装只提供一个 `elves.exe`，固定工具内嵌并按需释放。旧 launcher、管理器、注入脚本及任务看板入口删除。

桌面主窗口关闭收进托盘，明确退出才执行安全回收。回收按原生任务状态和未确认操作判断，结果未知时保留原始回执，不自动重发或把强制终止视为成功。
